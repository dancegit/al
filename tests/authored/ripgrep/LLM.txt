# ripgrep

> ripgrep is a command line tool (binary `rg`, package version 15.2.0) that recursively searches the current directory for a regex pattern, respecting gitignore rules and skipping hidden and binary files by default. It is written in Rust (edition 2024, minimum Rust 1.96) as a Cargo workspace: the root package builds `rg` from `crates/core/main.rs`, and nine library crates under `crates/` hold the search, regex, printing, glob and ignore logic. It is shipped as release binaries and a Debian package built by a GitHub Actions workflow on `x.y.z` tags, and published to crates.io by a maintainer.

## Layout

- `Cargo.toml` — root package `ripgrep`, binary `rg`, workspace members, feature `pcre2`, release profiles
- `build.rs` — build script: embeds the git revision hash and, on Windows MSVC, `pkg/windows/Manifest.xml`
- `crates/core` — the `rg` binary: `main.rs`, `search.rs`, `haystack.rs`, `messages.rs`, `logger.rs`; sources sit directly in this directory, not in `src/`
- `crates/core/flags` — CLI definition: `defs.rs` (one `Flag` implementation per logical flag, including its documentation; the order of `FLAGS` sets the order in `--help` and the man page), `parse.rs`, `lowargs.rs`, `hiargs.rs`, `config.rs`
- `crates/core/flags/doc` — generators and templates for `-h`, `--help` and the man page (`template.rg.1`, `template.long.help`, `template.short.help`)
- `crates/core/flags/complete` — shell completions; `rg.zsh` is written by hand and checked against `rg --help` by `ci/test-complete`
- `crates/matcher/src` — `grep-matcher`: the matcher trait the search core is written against
- `crates/regex/src` — `grep-regex`: matcher implementation on Rust's regex engine
- `crates/pcre2/src` — `grep-pcre2`: matcher implementation on PCRE2, compiled only with feature `pcre2`
- `crates/searcher/src` — `grep-searcher`: line-oriented and multi-line search over readers, files and memory maps
- `crates/printer/src` — `grep-printer`: standard, summary and JSON output
- `crates/grep` — `grep`: facade crate re-exporting the `grep-*` crates; example in `crates/grep/examples/simplegrep.rs`
- `crates/cli/src` — `grep-cli`: helpers for command line applications (decompression, hostname, patterns, stdin detection)
- `crates/globset/src` — `globset`: glob matching; benchmark in `crates/globset/benches/bench.rs`
- `crates/ignore/src` — `ignore`: gitignore matching and sequential and parallel directory walking; benchmarks in `crates/ignore/benches/workloads.rs`
- `tests` — integration tests of the `rg` binary, compiled as the single test target `integration` rooted at `tests/tests.rs`. Each test is an `rgtest!(name, |dir: Dir, mut cmd: TestCommand| { … })` item and runs a second time against PCRE2 when feature `pcre2` is on. Modules: `tests/feature.rs` (tests for new features go here), `tests/regression.rs` (one test per fixed issue, named `r<issue number>`, preceded by a `// See: <issue URL>` comment), `tests/binary.rs`, `tests/json.rs`, `tests/multiline.rs`, `tests/misc.rs` (do not add tests here), helpers `tests/util.rs`, `tests/macros.rs`, `tests/hay.rs`
- `tests/data` — compressed and binary fixtures for the integration tests
- `crates/ignore/tests` — integration tests of the `ignore` crate; each `<name>.rs` has a `<name>.gitignore` fixture beside it
- `crates/matcher/tests` — integration tests of `grep-matcher`, rooted at `crates/matcher/tests/tests.rs`
- Unit tests — in the source file they cover, inside `#[cfg(test)] mod tests { … }` (for example `crates/regex/src/strip.rs`, `crates/core/flags/defs.rs`)
- `fuzz` — separate cargo-fuzz crate with its own `fuzz/Cargo.lock`; one target, `fuzz/fuzz_targets/fuzz_glob.rs`
- `benchsuite` — benchmark runner `benchsuite/benchsuite` and recorded results under `benchsuite/runs`
- `ci` — scripts run by CI and at release: `ci/test-complete`, `ci/ubuntu-install-packages`, `ci/sha256-releases`, `ci/utils.sh`
- `pkg` — packaging: `pkg/brew/ripgrep-bin.rb`, `pkg/windows/Manifest.xml`; `HomebrewFormula` is a symlink to `pkg/brew`
- `scripts/copy-examples` — Python script that copies code blocks from a Rust file into an examples directory
- `.cargo/config.toml` — static linking flags for the Windows MSVC and x86_64 musl targets
- `rustfmt.toml` — formatter configuration
- `README.md`, `GUIDE.md`, `FAQ.md` — user documentation; `CHANGELOG.md` — release notes; each crate has its own `README.md`

## Conventions

- Rust code is formatted with `max_width = 79`, `use_small_heuristics = "max"`, `edition = "2024"`; `cargo fmt --all --check` must pass.
- Code must compile on Rust 1.96.0; do not use language or library features newer than that.
- A test for a new feature of `rg` goes in `tests/feature.rs`; do not add tests to `tests/misc.rs`.
- A test for a fixed bug goes in `tests/regression.rs` as `rgtest!(r<issue number>, …)` with a `// See: https://github.com/BurntSushi/ripgrep/issues/<issue number>` comment on the line above.
- Integration tests are written with `rgtest!` and must pass on both regex engines, because `rgtest!` runs each test again with PCRE2 when feature `pcre2` is enabled.
- A unit test goes in the `#[cfg(test)] mod tests` block of the source file it covers.
- A new or changed command line flag is one `Flag` implementation in `crates/core/flags/defs.rs`, listed in `FLAGS`, with its documentation in that implementation; the same options must be added to `crates/core/flags/complete/rg.zsh` so that `ci/test-complete` prints `OK`.
- A user-visible change adds an entry under the `TBD` heading at the top of `CHANGELOG.md`, in the form `* [BUG #<n>](<issue or pull request URL>):`, `* [FEATURE #<n>](<URL>):` or `* [PERF #<n>](<URL>):` followed by an indented one-sentence description.
- `Cargo.lock` and crate version numbers change only as part of a release (`RELEASE-CHECKLIST.md`).
- `AI_POLICY.md` applies to contributions to the upstream repository BurntSushi/ripgrep: autonomous agents are not allowed to contribute; issue and pull request text and replies to maintainers must be written by a human; AI output quoted in a comment must be in a quote block, disclosed, and accompanied by human commentary.
- Commit subject format `<area>: <summary> (#<pull request number>)`, with a body paragraph and a trailing `PR #<number>` line — UNVERIFIED: seen in the only commit in this checkout's history (`178cc02`); no file states it.

## Work classes

- Chore: formatting, rustdoc or comment fixes, documentation edits in `README.md`, `GUIDE.md`, `FAQ.md` or a crate `README.md`, a test-only change. Touches no behaviour of `rg`. Proven by `format`, `test` and, when rustdoc changed, `docs`.
- Bug: a wrong match, wrong output, wrong ignore decision or a crash, fixed in one crate under `crates/`. The regression test goes in `tests/regression.rs` as `r<issue number>` when the bug is visible through `rg`, otherwise in the crate's own `#[cfg(test)] mod tests` or `crates/<crate>/tests`. Add a `[BUG #<n>]` entry to `CHANGELOG.md`. Proven by `format`, `test`, `e2e`.
- Feature: a new flag or new behaviour of `rg`, or a new public item in a library crate. User-visible change is the standard output, standard error or exit status of `rg`, the text of `rg --help` and the generated man page, or a public API signature of a crate under `crates/`. Add a test in `tests/feature.rs`, the flag in `crates/core/flags/defs.rs` and `crates/core/flags/complete/rg.zsh`, and a `[FEATURE #<n>]` entry in `CHANGELOG.md`. Proven by the log of `test` (the new `rgtest!` asserts the exact output of `rg`), `e2e` and `docs`; no other artefact exists.
- Safe for zero-touch: none — command durations are UNVERIFIED, the only artefact is the log, and `AI_POLICY.md` requires a human in the loop.
