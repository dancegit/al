# jq

> jq is a command-line JSON processor and the C library `libjq`, written in portable C with no runtime dependencies. It is built with GNU autotools (autoconf, automake, libtool) and optionally links the vendored Oniguruma regex library (git submodule). It ships as standalone executables on GitHub releases, a source tarball (`make dist`), and a container image `ghcr.io/jqlang/jq`; the manual and website are generated from YAML with Python.

## Layout

- `src/` — C sources and headers of libjq and the `jq` binary (`src/main.c` is the CLI entry point; `src/builtin.c` C builtins; `src/builtin.jq` builtins written in jq; `src/lexer.l` and `src/parser.y` grammar sources)
- `src/lexer.c`, `src/lexer.h`, `src/parser.c`, `src/parser.h` — generated from `src/lexer.l` and `src/parser.y`, committed
- `tests/` — test suite run by `make check`. Driver shell scripts have no extension (`tests/jqtest`, `tests/mantest`, `tests/shtest`, `tests/utf8test`, `tests/base64test`, `tests/uritest`, `tests/optionaltest`, `tests/onigtest`, `tests/manonigtest`) and source `tests/setup`. Data files are `tests/<name>.test`: groups of three lines (program, input, expected output). `tests/modules/` holds jq module fixtures; `tests/jq_fuzz_*.c` and `tests/jq_fuzz_*.cpp` are fuzz harnesses
- `tests/man.test`, `tests/manonig.test` — generated from the manual examples, committed
- `docs/` — manual and website sources: `docs/content/manual/dev/manual.yml` (manual for the development version), `docs/content/manual/v*/manual.yml` (released versions), `docs/templates/`, `docs/public/`, Python build scripts `docs/build_manpage.py`, `docs/build_mantests.py`, `docs/build_website.py`, `docs/validate_manual_schema.py`, and `docs/Pipfile`
- `jq.1.prebuilt` — man page generated from `docs/content/manual/dev/manual.yml`, committed
- `Makefile.am`, `configure.ac` — autotools build definition; `Makefile.am` lists every source file, test driver (`TESTS`) and distributed file (`EXTRA_DIST`)
- `config/m4/`, `m4/` — autoconf macros
- `scripts/` — `scripts/version` (version string from git tags), `scripts/crosscompile`, `scripts/gen_utf8_tables.py`
- `vendor/decNumber/` — vendored decNumber library
- `vendor/oniguruma` — git submodule (empty until `install` runs)
- `sig/` — release signatures and release signing keys
- `.github/workflows/` — CI, release and website publishing
- `Dockerfile` — container image build
- `NEWS.md` — release notes per version
- `README.md` — entry document

## Conventions

- A test in `tests/jq.test` is three lines: jq program, input, expected output; blank lines and lines starting with `#` are ignored.
- A test for a language feature or builtin goes in `tests/jq.test`; a test that needs regex support goes in `tests/onig.test`; a test of command-line options or process behaviour goes in `tests/shtest`.
- A new test driver script must be added to `TESTS` in `Makefile.am`, and every new test data file to `EXTRA_DIST` in `Makefile.am`.
- A new C source or header file must be added to `LIBJQ_SRC` or `LIBJQ_INCS` in `Makefile.am`.
- Builtins that can be written in jq go in `src/builtin.jq`; C builtins go in `src/builtin.c`.
- Every user-visible builtin or option is documented in `docs/content/manual/dev/manual.yml`; its `examples` entries are tests.
- After changing `docs/content/manual/dev/manual.yml`, `tests/man.test`, `tests/manonig.test` and `jq.1.prebuilt` must be regenerated (`./configure --enable-docs` then `make jq.1.prebuilt tests/man.test tests/manonig.test`, needs pipenv); CI fails when they are out of date.
- Never hand-edit `src/lexer.c`, `src/lexer.h`, `src/parser.c`, `src/parser.h`; change `src/lexer.l` or `src/parser.y` and regenerate in maintainer mode.
- Building and running the tests must leave no change in tracked files (`git diff --exit-code` is run after `make check` in CI).
- C code must compile with `-Wextra -Wall -Wno-unused-parameter -Wno-unused-function -Woverlength-strings -Wstrict-prototypes`.
- Public libjq symbols start with `jq_` or `jv_` (only those are exported).
- Text files use LF line endings.
- Commit message format: UNVERIFIED (the checkout has one commit: `Fix mktime/0 to allow the last two seconds of 1969 (#3671)`).

## Work classes

- Chore: build-system, CI-free cleanup or documentation wording change; touches `Makefile.am`, `configure.ac`, `README.md` or `docs/content`; proven by `build` and `test`.
- Bug: a fix in `src/*.c` or `src/builtin.jq` with a regression test added to `tests/jq.test` (three-line group), `tests/onig.test` for regex, or `tests/shtest` for command-line behaviour; proven by `build` and `test`.
- Feature: a new builtin, operator or command-line option in `src/`, with tests in `tests/jq.test` or `tests/shtest` and a manual entry with examples in `docs/content/manual/dev/manual.yml`. User-visible change is the output of the `jq` CLI (stdout, stderr, exit code) and the public API in `src/jq.h` and `src/jv.h`; the artefact that proves it is `test-suite.log` with `tests/*.log` showing the new test passing.
- Safe for zero-touch: UNVERIFIED — the repository states no policy; `test` emits log artefacts but its duration is unknown.
