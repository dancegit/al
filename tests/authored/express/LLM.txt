# express

> express is a web framework for Node.js, published to the npm registry as the package `express` (version 5.3.0) and consumed by Node.js applications through `require('express')`. It is written in CommonJS JavaScript with no build step: `index.js` re-exports `lib/express.js`. It is tested with mocha and supertest, linted with eslint 8, and shipped by a GitHub Actions workflow that publishes to npm when a GitHub release is published.

## Layout

- `index.js` — package entry point; re-exports `lib/express.js`
- `lib/` — all library source: `application.js` (app), `express.js` (factory and exports), `request.js` (req), `response.js` (res), `utils.js`, `view.js`
- `test/` — mocha unit tests, one file per public member, named `test/<object>.<member>.js` (`test/res.send.js` tests `res.send` from `lib/response.js`; `test/req.query.js` tests `req.query` from `lib/request.js`; `test/app.param.js` tests `app.param` from `lib/application.js`); whole-module tests are `test/utils.js`, `test/view.js`, `test/Router.js`, `test/Route.js`. A new test for a member of `lib/response.js`, `lib/request.js` or `lib/application.js` goes in `test/res.<member>.js`, `test/req.<member>.js` or `test/app.<member>.js`
- `test/acceptance/` — mocha acceptance tests, one per example app, named `test/acceptance/<example>.js`; each requires `examples/<example>` and drives it with supertest
- `test/fixtures/` — template and static files read by tests
- `test/support/` — test helpers: `env.js` (preloaded by mocha; sets NODE_ENV=test), `tmpl.js`, `utils.js`
- `examples/` — runnable example applications, one directory per example (`examples/<example>/index.js`)
- `examples/README.md` — index of the examples
- `Readme.md` — entry document: installation, quick start, how to run tests
- `History.md` — changelog, newest release first
- `package.json` — manifest: dependencies, npm scripts, supported Node.js range
- `.eslintrc.yml` — eslint rules
- `.eslintignore` — paths eslint skips (`coverage`, `node_modules`)
- `.editorconfig` — whitespace rules
- `.npmrc` — npm settings: no lock file, lifecycle scripts ignored, minimum release age 7 days, git dependencies disallowed
- `.github/` — CI workflows and dependabot configuration
- `coverage/` — generated by nyc, not tracked (listed in `.gitignore`)
- docs path: none (documentation lives outside this repository)

## Conventions

- JavaScript is indented with 2 spaces; `SwitchCase` indent is 1 level (`.eslintrc.yml` `indent`, `.editorconfig`).
- Every file ends with a newline and has no trailing whitespace (`eol-last`, `no-trailing-spaces`).
- Comparisons use `===` / `!==`; `== null` is the only loose comparison allowed (`eqeqeq: allow-null`).
- No unused variables; unused function arguments are allowed (`no-unused-vars` with `args: none`).
- The global `Buffer` is forbidden; take `Buffer` from the `node:buffer` module (`no-restricted-globals`).
- No lock file is committed: `package-lock.json`, `npm-shrinkwrap.json` and `yarn.lock` are git-ignored and `.npmrc` sets `package-lock=false`.
- Tests are mocha `describe`/`it` blocks that issue HTTP requests with supertest; the outer `describe` names the object (`res`) and the inner one the member (`.send()`).
- A unit test goes in `test/<object>.<member>.js`; an acceptance test for `examples/<example>` goes in `test/acceptance/<example>.js`.
- Code must not create global variables: mocha runs with `--check-leaks`.
- Code must run on every Node.js version from 18 (package.json `engines`).
- Commit message format: UNVERIFIED (one commit visible in the checkout: `deps: body-parser@^2.4.0 (#7563)`).
- Changelog policy for `History.md`: UNVERIFIED.
- Contribution rules: UNVERIFIED (the Contributing Guide is in another repository, expressjs/.github).

## Work classes

- Chore: a dependency range change in `package.json`, an eslint rule or example clean-up, or a test-only addition; touches `package.json`, `examples/`, `test/`; proved by `lint` and `test`.
- Bug: a correction to behaviour of `app`, `req` or `res` in one file under `lib/`; the regression test goes in the existing `test/<object>.<member>.js` for that member (created if absent); proved by `lint` and `test`.
- Feature: a new or extended public member or option of `app`, `req`, `res` or the `express` exports in `lib/`, with tests in `test/<object>.<member>.js`. User-visible change is a public API signature or the HTTP response (status, headers, body) an application produces; the proof is the mocha spec output in the `test` log (the test names and pass counts) and `coverage/lcov.info` showing the changed lines executed.
- Safe for zero-touch: none (check durations and determinism are UNVERIFIED; the published package is a public API used by other projects)
