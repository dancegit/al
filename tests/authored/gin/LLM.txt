# gin

> Gin is an HTTP web framework written in Go, imported by other Go programs as the module `github.com/gin-gonic/gin` (`go.mod:1`). It consists of the root package `gin` (router, context, middleware) and the sub-packages `binding`, `render`, `codec/json`, `ginS` and `internal/*`. It is shipped by pushing a git tag, which runs GoReleaser in GitHub Actions to publish a GitHub release without building binaries (`.github/workflows/goreleaser.yml:5`, `.goreleaser.yaml:7`).

## Layout

- `*.go` (repository root, e.g. `gin.go`, `context.go`, `routergroup.go`, `tree.go`, `auth.go`, `logger.go`, `recovery.go`) — source of package `gin`; `test_helpers.go` is non-test source that exports test helpers
- `*_test.go` (repository root) — Go tests of package `gin`, in the same directory as the source; the test for `<name>.go` is `<name>_test.go` (e.g. `auth.go` and `auth_test.go`)
- `binding/` — request binding and validation (JSON, XML, form, query, URI, header, YAML, TOML, protobuf, msgpack, BSON); tests are `binding/*_test.go` beside the source
- `render/` — response renderers (JSON, XML, HTML, YAML, TOML, protobuf, msgpack, BSON, PDF, redirect, text, data, reader); tests are `render/*_test.go` beside the source
- `codec/json/` — JSON codec selected by build tag (`jsoniter`, `go_json`, `sonic`, default `encoding/json`); no test files
- `internal/bytesconv/`, `internal/fs/` — internal helpers; tests are `*_test.go` beside the source; these packages are not run by `make test` (`Makefile:7`)
- `ginS/` — package `ginS`, a default-engine API wrapper; test is `ginS/gins_test.go`
- `testdata/` — fixtures used by tests: `testdata/certificate/` (TLS certificate and key), `testdata/protoexample/` (protobuf definition and generated Go), `testdata/template/` (HTML templates), `testdata/test_file.txt`
- `docs/doc.md` — user documentation of every feature; `README.md` is the entry document
- `examples/README.md` — notice that examples live in another repository; no code
- `CHANGELOG.md` — release notes per version; `BENCHMARKS.md` — router benchmark report
- `Makefile` — developer targets `test`, `fmt`, `fmt-check`, `vet`, `lint`, `misspell`, `misspell-check`, `tools`
- `.golangci.yml` — golangci-lint v2 linter and formatter configuration; `codecov.yml` — coverage targets
- `.github/` — GitHub Actions workflows, issue and pull request templates, dependabot configuration
- `.goreleaser.yaml` — release configuration
- `go.mod`, `go.sum` — module manifest and checksums
- Generated output (untracked, listed in `.gitignore`): `coverage.out`, `profile.out`, `tmp.out`

## Conventions

- Open pull requests against the `master` branch (`CONTRIBUTING.md:34`).
- A pull request has at most two commits; squash otherwise (`CONTRIBUTING.md:35`).
- Every code change adds or modifies tests that cover it (`CONTRIBUTING.md:37`); the test goes in `<name>_test.go` in the same directory as the changed `<name>.go`.
- A new feature is documented in `docs/doc.md`, not in `README.md` (`CONTRIBUTING.md:38`).
- The pull request description follows the checklist in `.github/PULL_REQUEST_TEMPLATE.md` (`CONTRIBUTING.md:39`).
- Commit subjects use the form `<type>(<optional scope>): <subject>` with type one of `feat`, `fix`, `chore`, `refactor`, `build`, `ci`, `docs`; the release changelog groups commits by these prefixes (`.goreleaser.yaml:38-53`).
- Use `any`, not `interface{}` (`.golangci.yml:69-71`).
- Code is formatted with gofmt, gofumpt and goimports (`.golangci.yml:63-66`); `gin.go` is excluded from the formatters (`.golangci.yml:74-75`).
- Tests use `github.com/stretchr/testify` assertions and must pass the `testifylint` linter with all checks enabled (`go.mod:16`, `.golangci.yml:16`, `.golangci.yml:29-30`).
- Coverage targets are 99% for the project and 99% for the patch (`codecov.yml:8`, `codecov.yml:13`).
- Code must compile and pass tests under each of the build tag sets CI uses: none, `-tags nomsgpack`, `--ldflags="-checklinkname=0" -tags sonic`, `-tags go_json`, and `-race` (`.github/workflows/gin.yml:40-47`).

## Work classes

- Chore: dependency bump in `go.mod` and `go.sum`, a documentation fix in `docs/doc.md` or `README.md`, or a lint/format cleanup in `*.go` files; proven by `lint` and `test`.
- Bug: a fix in one source file (e.g. `context.go`, `tree.go`, `binding/form_mapping.go`) plus a regression test in the `<name>_test.go` file beside it; proven by `test`.
- Feature: a new or changed exported function, method, type or option of package `gin`, `binding` or `render` (the public Go API signature and the HTTP response it produces are what a user sees), with tests beside the source and a section in `docs/doc.md`; proven by `test` output and `coverage.out`.
- Safe for zero-touch: none (command durations are UNVERIFIED, `test` needs the network on a fresh checkout, and CI additionally runs a 20-job matrix that the local commands do not reproduce)
