# flask

> Flask is a Python WSGI web application framework distributed as the `Flask` package (version 3.2.0.dev, requires Python >=3.11). Application developers import it as a library and use its `flask` command line entry point (`flask.cli:main`). It is built on Werkzeug, Jinja, Click, ItsDangerous, MarkupSafe and Blinker, packaged with flit_core, managed with uv and tox, and shipped to PyPI by a GitHub Actions workflow that runs on tag push.

## Layout

- `src/flask` — the `flask` package: application object (`app.py`), blueprints, CLI (`cli.py`), config, contexts (`ctx.py`), helpers, sessions, templating, test client (`testing.py`), views, request/response wrappers
- `src/flask/sansio` — application, blueprint and scaffold base classes that must not do IO and must not use the Flask globals
- `src/flask/json` — JSON provider (`provider.py`) and tagged JSON serializer used by sessions (`tag.py`)
- `tests` — pytest tests in flat modules named `tests/test_<area>.py` (for example `src/flask/blueprints.py` is tested by `tests/test_blueprints.py`, `src/flask/json/tag.py` by `tests/test_json_tag.py`); test functions are named `test_<behaviour>`; shared fixtures are in `tests/conftest.py`; a new test goes into the existing `tests/test_<area>.py` module for the source file it covers
- `tests/test_apps` — fixture applications imported by the tests
- `tests/templates` — Jinja templates used by the tests
- `tests/static` — static files used by the tests
- `tests/type_check` — modules checked by mypy only (`typing_*.py`), not collected as pytest tests
- `docs` — Sphinx documentation in reStructuredText; configuration in `docs/conf.py`; build output goes to `docs/_build/` (git-ignored)
- `examples` — three example applications (`examples/celery`, `examples/javascript`, `examples/tutorial`), each with its own `pyproject.toml`; not covered by the root test command
- `CHANGES.rst` — changelog, newest version first
- `pyproject.toml` — package metadata, dependency groups, and pytest, coverage, mypy, ruff, codespell and tox configuration
- `.pre-commit-config.yaml` — pre-commit hooks: ruff-check, ruff-format, uv-lock, codespell, check-merge-conflict, debug-statements, fix-byte-order-marker, trailing-whitespace, end-of-file-fixer
- `.editorconfig` — indentation, line ending and line length rules
- `README.md` — entry document

## Conventions

- Python code passes `ruff check` with rule sets B, E, F, I, UP, W and `ruff format`; maximum line length is 88.
- Imports are one name per `from … import …` line (ruff isort `force-single-line = true`).
- Indentation is 4 spaces (2 spaces in css, html, js, json, yaml files); line endings are LF; files end with a newline and have no trailing whitespace.
- Code under `src` passes `mypy` with `strict = true`.
- Every warning raised during the tests fails the suite (`filterwarnings = ["error"]`).
- A code change adds tests that fail without the change, in the `tests/test_<area>.py` module of the source file it changes.
- A code change adds an entry to `CHANGES.rst` under the topmost (unreleased) version, written as a `-   ` bullet that ends with a ``:issue:`<number>` `` or ``:pr:`<number>` `` reference.
- A change to documented behaviour adds a `.. versionchanged:: <version>` (or `.. versionadded:: <version>`) entry in the docstring of the changed code and updates the relevant file under `docs`.
- Code under `src/flask/sansio` does no IO and does not use the Flask globals.
- A commit message is one lower-case imperative summary line without a type prefix (example: "add `versionchanged` for ctx signature change (#6176)").
- A pull request description links its issue with `fixes #<issue number>`.
- Dependencies are declared in `pyproject.toml` and locked in `uv.lock`; `uv.lock` is regenerated with uv, not edited by hand.

## Work classes

- Chore: dependency pin or lock update, tool configuration change in `pyproject.toml`, documentation correction under `docs`, removal of deprecated code; touches `pyproject.toml`, `docs`, `CHANGES.rst`; proved by `lint`, `typecheck` and `test` (and `docs` when files under `docs` change).
- Bug: a behaviour correction in one module under `src/flask`; the regression test goes into the matching `tests/test_<area>.py` (issue-specific regressions with no matching module go into `tests/test_regression.py`); adds a `CHANGES.rst` entry; proved by `lint`, `typecheck` and `test`.
- Feature: a new or changed public API of the `flask` package (a method, decorator, parameter or config key on `Flask`, `Blueprint`, the request/response wrappers or the test client) or a new option or output of the `flask` command line; user-visible as a public API signature, an HTTP response produced by a view under the test client, or CLI output; adds tests, a `CHANGES.rst` entry, `.. versionadded::` / `.. versionchanged::` docstring entries and documentation under `docs`; proved by the junit report from `test` listing the new test cases as passed.
- Safe for zero-touch: UNVERIFIED — chore and bug are the candidate classes: `lint`, `typecheck` and `test` are deterministic (dependencies locked by `uv.lock`, warnings are errors, no services needed) and `test` emits a junit report; check durations are not stated in the repository, so "fast" is not confirmed.
