# Agentic layer — al

Agentic layer for al, the generator of agentic layers

Generated by `al gen` from `agentic.rkt` (derived from `LLM.txt`). This directory is the agentic layer of the repository it sits in (`agentic/`, placement `in-repo`) and is committed with the code. It changes how agents work on that repository; it is not application code, and ordinary runs may not change it (see below). Agents work in
git worktrees under `trees/`, plans land in `specs/`, run state and logs in `agents/<adw-id>/`, proof in
`artefacts/<adw-id>/`.

## Run

```bash
uv run agentic/adws/adw_plan-build.py "your high-level prompt"          # manual trigger
uv run agentic/adws/adw_plan-build.py "…" --dry-run                     # mock agent, no LLM
uv run agentic/adws/dispatch.py --source tasklist:<line>                             # from a prompt input
```

## Models and spending

- Agent `claude-code` (claude-code): `base` = `claude-opus-5-5`, `heavy` = `claude-opus-5-5`.

Every command and hop runs on a tier (its `#:model-set`); a run step may name its own. For one run,
without changing `agentic.rkt`:

```bash
uv run agentic/adws/adw_plan-build.py "…" --model-set heavy               # every agent step on one tier
uv run agentic/adws/adw_plan-build.py "…" --model heavy=MODEL_ID          # another model for a tier (repeatable)
uv run agentic/adws/adw_plan-build.py "…" --max-cost 3                    # hand over once the run costs more than $3
```

The same as environment variables, which the triggers and `al improve` pass on: `AL_MODEL_SET=TIER`,
`AL_MODELS="heavy=…,base=…"`, `AL_MAX_COST=USD`. Flags win. A task-file tag (`{heavy}`) or an issue
keyword (`adw: <workflow> heavy`) naming any declared tier selects it for the steps that do not set their
own. Which tier wins: `--model-set`, then the step's own `#:model-set`, then the request's tier, then the
command's; `--model` then picks that tier's model id. `state.json` (`agent_calls`) and the run's events
record the tier, model and reason of every agent call; `--help` of any workflow script says the same.

Spending limits: none declared (add `(budget limits #:run-usd … #:day-usd …)`); `--max-cost` still limits one run.

## Change the layer

The layer has two kinds of source: `agentic.rkt` (language reference: `AL-DSL.llms.txt`) and the
layer-local templates under `templates/`. Everything else here is generated by `al gen agentic`.

- A short, permanent instruction for one prompt: a `#:focus` line on that command in `agentic.rkt`.
- A bigger change to a prompt: `al eject <layer> command NAME` copies the kit template it uses into
  `templates/commands/`; edit the copy there (its `{{placeholders}}` stay). `al eject <layer> --list`
  shows which templates are yours and whether the kit has changed since.
- A reviewed change, made by al's own workflow and ending in a pull request:
  `al improve <layer> "what to change, in plain words"`.
- Never edit a generated file. `al gen` notices a hand edit, writes nothing, and says how to keep it
  (`al eject …`) or drop it (`al gen <layer> --discard-edits`).

An ordinary workflow that changes anything under `agentic/` in its worktree is stopped at the gate with a
`protected-path:` reason and goes to a person: only a workflow with `#:changes layer` (the one
`al improve` runs) may change the layer.

## What is committed

Committed: `agentic.rkt`, `LLM.txt`, `templates/`, `mock/`, `adopted/` (what `al adopt` wrote), and expert `expertise.yaml` files (source); `agentic-layer.json`, `conditional_docs.md`, `commands/`, `hops/`, `experts/`, `adws/`, `env/`, `fabric/`, `forge/`, `AL-DSL.llms.txt`, this README, `.gitignore` and `.al-manifest.json` (generated; the manifest lets `al gen` notice hand edits).

Not committed (`.gitignore`, written by `al gen`): run state (worktrees, run logs, artefacts, plans, run documents, the task list and spec inbox, `al improve` runs), files that name this machine's paths (`bin/al`, systemd units, the Home Manager module), private values (`local.env`) and caches.
