# al

> `al` generates an agentic layer (prompts, workflows, sandbox, triggers, a dashboard) for any git repository. An LLM writes a description (`LLM.txt`) and a short definition (`agentic.rkt`) in a small Racket language; a compiler checks the definition and a generator produces the layer from templates. It is used by developers from a clone of this repository through the `tools/al` command (Python, run with `uv`); the language and compiler are Racket; the runtime that executes workflows and the dashboard are Python with the standard library only. Nothing is packaged or published: the repository is the product.

## Layout

- `racket/al/` — the layer language `#lang al`: `private/meta.rkt` (meta-DSL), `private/vocab.rkt` (the vocabulary), `private/compiler.rkt`, `private/schema.rkt`, `private/reference.rkt`, `cli.rkt`, `examples/`
- `racket/al/tests/` — compiler tests, run with `raco test`; files are named `*-test.rkt`, fixtures in `racket/al/tests/fixtures/`
- `tools/` — `tools/al` (the command: init, scout, compile, gen, explain, check, eject, improve, dashboard, verify), `tools/explain.py`, `tools/al_improve.py`, `tools/demo/` (demo recording scripts)
- `kit/runtime/` — what runs a workflow: `adw_modules/*.py`, `dispatch.py`, `triggers/`, `voice/`
- `kit/runtime/tests/` — pytest unit tests of the runtime, one `test_<module or topic>.py` per area; a new test for `kit/runtime/adw_modules/X.py` goes in `kit/runtime/tests/test_X.py`
- `kit/templates/` — the prompt templates every layer starts from (`commands/`, `hops/`, `experts/`)
- `kit/schemas/` — JSON output contracts of the classify, review and test commands
- `kit/dashboard/` — the live read-only dashboard: `dashboard.py` (server and model), `static/` (page), `demo/` (recording scripts)
- `kit/dashboard/tests/` — pytest tests of the dashboard: `test_model.py`, `test_events_model.py`, `test_server.py`, and real-browser tests `test_browser*.py`; fixtures are code in `fixtures.py` and `fixtures_events.py`
- `kit/self/` — the layer definition template used by `al improve`
- `meta/` — the prompts that guide an LLM through describing a codebase and writing its layer, and `LLM.txt.template.md`
- `schemas/agentic-layer-v1.schema.json` — JSON Schema of the compiled layer, generated from the vocabulary
- `tests/integration/` — pytest integration suite over five pinned public repositories; `golden/` holds snapshots of generated prompts; `testbeds.toml` pins the repositories
- `tests/tools/` — pytest tests of the `al` command itself (eject, in-repo layers, `al improve`, dashboard generation); a new test for `tools/explain.py` or `tools/al` goes here as `tests/tools/test_<topic>.py`
- `tests/authored/` — the five LLM-authored example layers (`LLM.txt` and `agentic.rkt` each), kept exactly as written
- `tests/webdemo/`, `tests/rotademo/`, `tests/selfdemo/`, `tests/forge/` — demo applications and live scripts that need a real agent or a throwaway forge
- `docs/` — `GUIDE.md`, `DESIGN.md`, `CASE-STUDY.md`, `ARTEFACTS.md`, `AL-DSL.llms.txt` (generated language reference)
- `docs/demo/` — recorded outputs of real runs (video, GIF, screenshots, logs)
- `agentic/` — this agentic layer (in-repo)
- Entry document: `README.md`

## Conventions

- `racket/al/private/vocab.rkt` is the single source for the compiler's forms, `schemas/agentic-layer-v1.schema.json` and `docs/AL-DSL.llms.txt`; the schema and the reference are regenerated from it and never edited by hand.
- A change to a kit template (`kit/templates/`) changes generated prompts: update the snapshots with `--update-golden` on the integration suite and include the reviewed snapshot diff in the same change.
- Never mention a private repository, a real employer or a real customer in any committed file; examples use public repositories or synthetic data only.
- No personal paths in committed files: no home directory, user name or machine-specific absolute path; write `~/code/myapp` style placeholders or paths relative to the repository root.
- Tests must not need the network unless they carry the `network` marker (integration suite) and must not call a real LLM: agent steps in tests use the mock agent or `--dry-run`.
- A test that needs podman, nix or a browser carries the matching marker (`podman`, `nix`, `browser`) and skips when the tool is missing; it never downloads one.
- Python code targets Python >=3.11, uses `from __future__ import annotations` and the standard library only in `kit/runtime` and `kit/dashboard`; a script that needs a third-party package declares it in its inline `# /// script` header.
- Tests never write into the repository checkout: they work in pytest's temporary directory and leave no branch, worktree or container behind.
- Files under `docs/demo/` are recordings of real commands; they are produced by running the demo scripts, never written by hand.
- Prose in `README.md` and `docs/` is plain and factual: short sentences, no marketing adjectives, numbers only from real runs.
- The layer in `agentic/` is not changed by ordinary work: the definition and templates change through `al improve`, generated files only through `al gen`.
- Commit messages are one lower-case summary line naming the area first (e.g. `dashboard: …`), no trailer lines.

## Protected paths

The language core (`racket/al/private`) is deliberately not protected: every workflow ends with a person's
review. `docs/AL-DSL.llms.txt` and `schemas/agentic-layer-v1.schema.json` are generated from the vocabulary
and must be regenerated, never edited by hand, whenever it changes.

- `kit/runtime/adw_modules/review.py` — the review and shipping gate
- `kit/runtime/adw_modules/ship.py` — the shipping gate (merge, deploy, pull request fallback)
- `kit/runtime/adw_modules/gitsafe.py` — git integrity checks around the sandbox
- `kit/runtime/adw_modules/envs.py` — the sandbox (worktree, nix, podman environments)
- `docs/demo` — recorded outputs of real runs
- `tests/authored` — LLM-authored example layers, kept exactly as written
- `tests/integration/testbeds.toml` — the pinned commits of the example repositories

## Work classes

- Chore: a missing unit test, a documentation or docstring correction, a test fixture; touches `tests/tools`, `kit/runtime/tests`, `kit/dashboard/tests`, `racket/al/tests` or prose; proved by the test command of the area touched; a change to the dashboard page (`kit/dashboard/static`) is proved by `test-dashboard-browser`.
- Bug: a wrong behaviour of `tools/al`, the runtime or the dashboard; the regression test goes in the test directory of that area (`tests/tools`, `kit/runtime/tests`, `kit/dashboard/tests`) and fails before the fix.
- Feature: a new `al` subcommand or option, a new vocabulary kind, a new dashboard view; user-visible as CLI output, a generated file or a dashboard screen; a vocabulary change needs a human because it is under a protected path.
- Safe for zero-touch: none

## Unknowns

- `test-dashboard-browser` is not deterministic on the machine where this file was written: `tests/test_browser_events.py::test_a_running_checks_log_is_followed_live_then_settles` failed in 5 of 10 runs on an idle machine (the `.log` element is read while it is empty). The command is declared because the repository documents it, but workflows use `test-dashboard` as their check until a human fixes the test or the page.
- `README.md:417` and `tests/README.md:5` give the compiler test command as `raco test racket/al/tests`. `al verify` showed that it exits 1 on a clean checkout with Racket 9.3: `raco test` on the directory also loads `racket/al/tests/fixtures/dangling-ref.rkt`, a definition that is invalid on purpose. The command declared here names the test file, as `tools/demo/scenes.toml:75` does. A human should correct the two documents or move the fixture.
- Repo URL and forge: the checkout has a remote, deliberately not recorded; the layer must work for any clone, so results are local branches and `PR.md`.
- License: no licence file is tracked.
- The command that regenerates `docs/AL-DSL.llms.txt` and `schemas/agentic-layer-v1.schema.json` from the vocabulary is not written in any document: UNVERIFIED, so no such command is declared.
- No lint, format or typecheck command exists in the repository.
- junit or coverage output: pytest could emit it, but no configuration in the repository says where; none declared.
- Durations in the Commands table are measured with `al verify` on one machine (see `docs/GUIDE-FINDINGS.md`), not taken from CI; there is no CI.
- The conventions marked "stated by the maintainer" in Evidence should be written into a CONTRIBUTING file.
