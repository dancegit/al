# #lang al — agentic layer DSL reference

> Generated from racket/al/private/vocab.rkt. Do not edit. This is the complete language:
> anything not listed here does not exist and will be rejected by the compiler.

## Shape of a file

```racket
#lang al
(agentic-layer #:name "repo-name" #:description "…" #:llm-txt "LLM.txt"
  (codebase #:root "…" #:languages (…) (cmd NAME "shell") … (paths …) (conditional-doc "path" "when") … (include "FILE") …)
  (FAMILY KIND #:id ID #:field value …) …   ; options, see families below
  (command NAME #:template T …) …
  (hop NAME #:template T …) …
  (expert NAME …) …
  (adw NAME #:input (…) #:trigger (…) #:environment (…) #:review ID #:agent ID
    (steps (run NAME …) (check NAME …) (script NAME …) (fan-out NAME …) (review) (ship) (compose ADW) …)) …
  (stage NAME #:branch "…" #:from STAGE #:into STAGE …) …   ; where work is delivered, see record `stage`
  (delivery PRESET #:param value …)          ; at most one; stands for stage and cycle clauses, see Delivery presets
  (promotion FROM -> TO #:approval human …)   ; how a stage moves into the next (al promote)
  (placement auto #:hosts (…) …)              ; at most one; where runs may execute, see family `placement`
  (include "FILE") …)                       ; more clauses from FILE, e.g. what `al adopt` wrote
```

Syntax notes: strings use double quotes; names are bare symbols; lists are parenthesised without
quotes or commas, e.g. `(python rust)` or `("src" "tests")`; booleans are `#t` / `#f`; exactly one
`(agentic-layer …)` form per file. Every field is `#:keyword value`. Omitted fields take the default.
Families with a default kind may be omitted entirely. `(cmd NAME "shell" …)` and
`(conditional-doc "path" "when")` take their first values positionally, exactly as shown.
A record type such as `model-tier` is written as a small list: its positional values, then `#:keyword value`
pairs, e.g. `#:models ((fast "claude-haiku-5-5") (heavy "claude-fable-5-2" #:effort high))`.

## Rules the compiler enforces

- Exactly one (codebase …) clause and at least one (adw …) clause.
- Every name is declared before it is used anywhere: (ref X) fields must name a declared option id, command, hop, cmd, artefact or adw.
- Option ids default to the kind name; give #:id when you declare two options of the same kind.
- Command and hop names share one namespace; step names are unique within an ADW (after compose expansion).
- A (ship) step must come after a (review) step in the same ADW.
- An ADW whose review option is `auto` with #:ship merge or deploy must contain at least one (check …) step before its (review) step, and #:require-checks must not be empty: zero-touch needs a closed loop.
- #:ship deploy needs #:deploy-cmd on the review option or on every stage the ADW delivers to.
- prompt-input `issue`, trigger `forge-actions`, and webhook issue events need a forge other than `none`.
- prompt-input `voice` and trigger `voice` need a (voice …) declaration.
- (voice kokoro …): #:max-utterance-seconds is 5–120; #:helper-agent, when given, names a declared agent; #:helper-model-set is a tier of the helper's agent (the first declared agent when #:helper-agent is empty).
- An ADW's environment stack has at most one option per kind; `host` cannot be combined with `worktree`; an ADW with run steps that write needs `worktree`.
- claude-code #:permission-mode bypassPermissions is only accepted for ADWs whose environment stack contains a podman option with #:agent-inside #t (the agent itself must be sandboxed).
- An ADW whose review option is `auto` with #:ship merge or deploy must have a podman option in its environment stack: nothing ships untouched from an unsandboxed environment.
- (compose ADW) inlines another ADW's steps; cycles are rejected.
- (fan-out NAME #:adw CHILD …): CHILD is a declared ADW other than the parent, with no cycle through fan-out or compose; CHILD (after compose expansion) contains no (ship) and no (fan-out) step and has a `worktree` environment, so each candidate ends with its work committed on its own branch; #:count is 2–8 and #:max-parallel 0–#:count; the fan-out step comes before the parent's (review) and (ship) steps; the parent has a `worktree` environment.
- A child ADW used by (fan-out …) must leave its changes committed (e.g. a final (run commit #:command commit) step): a candidate that committed nothing counts as failed.
- (layer in-repo #:dir D): D is a relative path inside the repository (no `..`, no leading `/`), and (codebase #:root …) is the way back up from D to the repository root: ".." for a top-level directory, "../.." for D = "tools/agentic".
- An ADW with #:changes layer must use a review option of kind `human` or `agent`: a change to how agents work always passes a person.
- (dashboard …) is declared at most once; omitted, it is (dashboard local) on 127.0.0.1:8765. A #:bind that is not a loopback address (127.x.x.x, ::1, localhost) needs #:token-env naming the environment variable that holds the access token; #:port is 1–65535 and #:poll-ms at least 100.
- Model tiers: an agent's tiers are `base` and `heavy` (from #:model-base / #:model-heavy, which have defaults) plus every (TIER "MODEL") in its #:models; a tier given both ways, or twice, is an error, and `inherit` is not a tier name. Every tier a workflow can use must be declared on the agent that runs it: run steps (their #:model-set, else their command's) on the step's #:agent or the ADW's agent; check #:resolve commands and review #:patch / #:implement commands on the ADW's agent; the review command on the review option's #:agent, else the ADW's agent. The mock agent accepts every tier. #:effort is only available for claude-code and codex (codex: not `max`).
- (budget limits …) is declared at most once; every limit given is greater than 0; #:limit-stop-percent is 0–100 (0 = off), #:on-limit wait needs a #:limit-stop-percent above 0, and #:limit-wait-minutes is at least 1.
- (stand-in off|suggest|auto …) is declared at most once; omitted, the stand-in is off. #:may and #:never share no kind; kind auto needs a non-empty #:may; #:max-actions-per-run is 1–20 and #:max-per-hour 1–1000; #:escalate-to lists at least one of dashboard, notify, and notify needs a notifier that lists needs-human; #:model-set is a tier declared on the agent of every ADW.
- #:may land needs a review option of kind auto with #:ship merge or deploy used by an ADW with a (ship) step; #:may promote needs declared stages; #:systemd #t needs (dashboard local).
- (notify …): #:to-env, #:from-env and #:smtp-url-env of `email` take the NAME of an environment variable in capitals (A–Z, 0–9, _); a value that looks like an e-mail address, a URL or a host name is rejected, because the layer file is committed. #:events lists at least one event and #:timeout is 1–60. Two notifiers of the same kind need #:id.
- A (script …) step needs a `worktree` environment in the ADW's stack, like check and ship. #:waiting-exit codes are 1–255; #:journal is a path relative to the worktree, without `..` or a leading `/`, whose only placeholder is `{adw_id}`.
- (include "FILE") splices the clauses of FILE (plain s-expressions, no #lang line; a path relative to agentic.rkt) where it stands: at the top level of (agentic-layer …), or inside (codebase …) for cmd, paths and conditional-doc clauses. Errors point into FILE. An included file cannot include another. `al adopt` writes its declarations this way.
- Stages: names are unique; #:from and #:into name declared stages; following #:into (default #:from) from every stage reaches the one final stage (no #:from, no #:into) without a cycle; the final stage's #:branch has no placeholder and equals (codebase #:default-branch …); stage branches are unique.
- A stage #:branch is a valid git branch name after its placeholders are filled; placeholders are {cycle}, {version} (only on the (cycle …) #:stage) and {date}.
- (cycle sprint|release …) needs declared stages; its #:stage is a declared stage that is not the final one and whose #:branch contains {cycle} (release: {cycle} or {version}); sprint #:length-days is 1–366; #:name uses only {year} {week} {n} {date} {version}, and a release #:name contains {version}.
- #:deliver-to names a declared stage and needs stages. Every class an ADW with a (ship) step can produce (#:classes, or all four) routes to a stage: its #:deliver-to, which must accept each of those classes, else the first declared stage that accepts the class, else the final stage. Without any stage, runs use (codebase #:default-branch …) exactly as before, and the IR has no stages, cycle or delivery key.
- A zero-touch ADW (review auto with #:ship merge or deploy) may only deliver to stages with #:agents-may-merge #t.
- #:entry fast-forward is rejected with every forge (github, forgejo): a pull request is merged by merge, squash or rebase.
- (delivery PRESET #:param value …) is declared at most once and expands to (stage …) and (cycle …) clauses (see Delivery presets); a (stage NAME …) with the name of a preset's stage replaces it, another name adds a stage; a (cycle …) next to a preset that declares one is an error.
- (promotion FROM -> TO …) needs declared stages; FROM and TO are declared stages, TO is FROM's #:into (default #:from), and each stage has at most one promotion. Every non-final stage without a declared promotion gets one with the defaults (origin "default").
- #:approval agent or auto is rejected for a promotion into a stage with #:agents-may-merge #f; #:approvers is 1–9.
- A hotfix promotion (FROM's #:from and #:into are TO, TO is the final stage, and no other stage goes into FROM) may not use #:approval auto; without #:back-merge it is merged back into every other stage that accepts a class.
- #:tag uses only {version} {cycle} {date} and is a valid tag name once filled; {version} needs #:version; {cycle} needs FROM to be the (cycle …) #:stage.
- #:after items are (deploy) or (deploy ENV): TO needs a #:deploy-cmd, and ENV equals TO's #:environment-name.
- #:back-merge names declared stages other than FROM and TO.
- A stage #:frozen period is "YYYY-MM-DD..YYYY-MM-DD" with valid dates, the first not after the second.
- #:may-commit #t is rejected on a read-only template (review, classify, question, pull-request, branch-name, summarize): those steps never commit.
- (host #:id ID …) is written with keywords only and may be declared several times, each with a unique #:id of lowercase letters, digits and dashes (no dots: an id is not a host name). It needs (layer in-repo …). Every name in #:units is a unit the layer declares (a cron or webhook trigger, a dashboard other than none); #:dashboard-port is 0 or 1–65535, and a non-zero port needs the dashboard unit. #:images pull needs a (registry …); #:images pull and load need a podman environment.
- (registry …) is declared at most once. #:address-env, #:username-env and #:password-env take the NAME of an environment variable in capitals; a value that looks like a URL, an e-mail address or a host name is rejected. #:username-env and #:password-env are given both or neither.
- (placement auto …) is declared at most once. #:hosts is not empty and has no duplicate; every name is `home` or the #:id of a declared (host …). #:max-runs-per-host is 0–64 and #:lost-after 30–3600. #:reserve names a host of #:hosts other than `home`, with at least one class. #:source-env and #:layer-source-env take the NAME of an environment variable in capitals; a value that looks like a URL, an e-mail address or a host name is rejected.
- `home` is a reserved host id, the machine that holds the layer: (host #:id home) is rejected. Host addresses are never in the layer file; they come from AL_HOST_<ID> in the environment or `local.env`.
- (cmd NAME "…" #:needs-home #t) needs no (placement …). With a placement, a workflow stays on `home` when a cmd it runs as a check or script, or that its review requires (#:require-checks), has #:needs-home #t; when it has a (script … #:waiting-exit …) step; when it changes the layer (#:changes layer); or when it has no `worktree` environment. `al explain` says which.
- (toolchain nix …) is used by an environment with #:toolchain ID. An environment gives #:toolchain or #:packages, never both. With #:toolchain, a nix-devshell gives no #:nixpkgs and a podman gives no #:base-image and no #:nested-engine #t. A nix-devshell or home-manager gives one of the two. A toolchain lists at least one package or feature, and its #:env names are variable names. Feature agent-cli needs a workflow whose agent runs inside an environment using the toolchain (a nix-devshell, or podman with #:agent-inside #t); the agents of those workflows are claude-code, codex or mock.
- Environment sources: a podman option takes its image from at most one of #:base-image, #:containerfile, #:devcontainer; #:target and #:context need #:containerfile; paths are relative to the repository root, without `..` or a leading `/`. A nix-devshell option needs #:packages or #:flake; #:shell needs #:flake. Only the first declared podman option may use #:containerfile or #:devcontainer and only the first nix-devshell option may use #:flake (the layer has one image and one flake). #:prepare names declared codebase cmds; an ADW whose worktree option prepares has no step named `prepare`.
- Kinds marked planned compile but are refused by the generator.
- A (check …) #:in names a podman or nix-devshell environment option; the check runs in the run's worktree inside it instead of the ADW's stack. A zero-touch ADW whose check runs #:in a nix-devshell option gets a warning: that check runs outside the sandbox.
- (check …) #:max-skipped is -1 (no limit) or more.
- (cmd … #:always #f) needs a non-empty #:covers; a #:covers entry is a path or glob relative to the repository root, without `..` and without a leading `/`.
- (check NAME #:cmds affected …) takes no #:cmd and no #:when-affected; at least one codebase cmd must declare #:covers; the steps it stands for are named after their cmds, so those names must be free in the ADW.
- A review with #:require affected and #:ship merge or deploy compiles with a warning: required checks no changed path touches are not run before the change ships without a person.
- (cmd … #:targeted T): T contains {tests}, {files} or {packages} and no other {…} placeholder; `path-map` in #:select needs #:path-map, `command` needs #:select-cmd (and #:select-cmd needs `command`), `coverage` needs #:record-coverage; #:max-targeted is at least 1; #:record-coverage other than none needs #:coverage-run and #:coverage-file; #:test-root, #:coverage-file and #:path-map patterns are relative, without `..` or a leading `/`, and path-map patterns use only {name} and {dir}.
- (testing …) is declared at most once; #:escalate items are (paths G …), (diff-lines N), (files N), (lockfile), (layer), (unmapped), (class C …); #:batch items are (every N) and (after-hours H), N and H at least 1; an item and the field it stands for are not both given; #:max-miss-percent is 0–100.
- Without (testing …) every check runs its full form. A zero-touch ADW (review auto with #:ship merge or deploy) whose runs can land on the final stage (no stages, or a class routed to the final stage) at a #:per-run depth other than full needs #:batch-every or #:batch-after-hours: the full suites must be proven per batch on that branch.

## Option families

### `layer`

Where the generated agentic layer lives. Only `in-repo` puts it inside the application repository; the others keep it out of the application tree.
Declare at most one. Default when omitted: `(layer sibling)`.

- **`(layer sibling …)`** — A directory next to the application checkout (default: <app>.al).
  - `#:dir` (string; default "") — Layer directory; empty = `<codebase root>.al` beside the app.
  - `#:git` (boolean; default #t) — Initialise the layer as its own git repository.

- **`(layer central …)`** — A directory under a central layers home, e.g. ~/agentic-layers/<name>.
  - `#:home` (string; default "~/agentic-layers") — Parent directory of all layers.
  - `#:git` (boolean; default #t) — Initialise the layer as its own git repository.

- **`(layer separate-repo …)`** — The layer is its own remote repository; the app is referenced by URL only.
  - `#:remote` (string; default REQUIRED) — Git remote URL of the layer repository.
  - `#:dir` (string; default "") — Local checkout directory; empty = `<name>.al`.

- **`(layer in-repo …)`** — The layer is a directory INSIDE the application repository, committed with the code. agentic.rkt lives in that directory and (codebase #:root …) is the way back up to the repository root (".." for a top-level directory). Run state (worktrees, run logs, artefacts, plans, the task list) stays in git-ignored directories of the layer, and every ADW that does not change the layer itself treats the layer directory as a protected path.
  - `#:dir` (string; default "agentic") — Layer directory relative to the repository root (no `..`, no leading `/`).

### `agent`

The coding agent a step runs on. ADWs name one; the runtime shells out to it headlessly. An agent offers named model tiers: `base` and `heavy` always exist (see #:model-base / #:model-heavy), and #:models adds any others. Commands, hops and run steps pick a tier with #:model-set.
Declare any number. Default when omitted: `(agent claude-code)`.

- **`(agent claude-code …)`** — Claude Code in programmable mode (`claude -p`), stream-json output.
  - `#:models` (list of (TIER MODEL [#:field value …]), see record `model-tier`; default ()) — Named model tiers, e.g. ((fast "claude-haiku-5-5") (heavy "claude-fable-5-2" #:effort high)). `base` and `heavy` may be given here instead of with #:model-base / #:model-heavy, but not both ways.
  - `#:model-base` (string; shorthand for the `base` entry of #:models; default "claude-opus-5-5") — Model of the `base` tier (routine steps: classify, commit, branch name, document).
  - `#:model-heavy` (string; shorthand for the `heavy` entry of #:models; default "claude-opus-5-5") — Model of the `heavy` tier (planning, building, review).
  - `#:permission-mode` (acceptEdits | bypassPermissions | plan | default; default acceptEdits) — Headless permission mode. bypassPermissions only inside a podman environment.
  - `#:safe-mode` (boolean; default #t) — Run with --safe-mode so user CLAUDE.md, hooks, plugins and skills are not loaded.
  - `#:allowed-tools` (list of string; default ("Read" "Glob" "Grep" "Edit" "Write" "Bash")) — Tools the headless agent may use without asking (passed as --allowedTools). Narrow it for read-only workflows.
  - `#:max-turns` (integer; default 600) — Turn cap per step (about two and a half hours of work at a usual pace).
  - `#:timeout` (integer; default 9000) — Wall-clock seconds per step.

- **`(agent codex …)`** — OpenAI Codex CLI (`codex exec`). It reports no cost, so spending limits count its calls as $0.
  - `#:models` (list of (TIER MODEL [#:field value …]), see record `model-tier`; default ()) — Named model tiers (see claude-code).
  - `#:model-base` (string; shorthand for the `base` entry of #:models; default "gpt-5.4-mini") — Model of the `base` tier.
  - `#:model-heavy` (string; shorthand for the `heavy` entry of #:models; default "gpt-5.4") — Model of the `heavy` tier.
  - `#:sandbox` (read-only | workspace-write | danger-full-access; default workspace-write) — Codex sandbox mode.
  - `#:timeout` (integer; default 9000) — Wall-clock seconds per step.

- **`(agent custom …)`** — Any CLI agent. The command receives the rendered prompt on stdin. It reports no cost, so spending limits count its calls as $0.
  - `#:command` (string; default REQUIRED) — Shell command; {model} and {cwd} are substituted.
  - `#:models` (list of (TIER MODEL [#:field value …]), see record `model-tier`; default ()) — Named model tiers (see claude-code); #:effort is not available.
  - `#:model-base` (string; shorthand for the `base` entry of #:models; default "") — Model of the `base` tier.
  - `#:model-heavy` (string; shorthand for the `heavy` entry of #:models; default "") — Model of the `heavy` tier.
  - `#:timeout` (integer; default 9000) — Wall-clock seconds per step.

- **`(agent mock …)`** — Deterministic stand-in used by tests and dry runs: no LLM, replays scripted responses. It accepts every tier name.
  - `#:script-dir` (string; default "mock") — Directory (in the layer) holding <step>.json scripted responses and optional <step>.patch files.
  - `#:timeout` (integer; default 60) — Wall-clock seconds per step.

### `budget`

Spending limits for agent work, in US dollars, counted from the cost each agent call reports (Claude Code reports it; codex and custom agents do not and count as $0). Omitted: no limits. A run that crosses a limit is stopped after the agent call that crossed it, never in the middle of one, and handed to a person like any other stopped run.
Declare at most one. Default when omitted: none.

- **`(budget limits …)`** — Limits on what agent calls may cost. Each is optional; an omitted one is no limit.
  - `#:run-usd` (number ≥ 0, e.g. 5 or 2.5; default none) — Most one run may spend (the sum of its agent calls). A per-run `--max-cost USD` (or AL_MAX_COST) replaces it for that run.
  - `#:step-usd` (number ≥ 0, e.g. 5 or 2.5; default none) — Most one agent call may spend. With Claude Code the call is also capped natively (--max-budget-usd), so it stops early.
  - `#:day-usd` (number ≥ 0, e.g. 5 or 2.5; default none) — Most this layer may spend per local calendar day, over all its runs. Once reached, no run and no agent step starts until the next day.
  - `#:limit-stop-percent` (integer; default 0) — Subscription usage threshold, 1-100: once the agent CLI reports that this share of a usage window (Claude Code: the 5-hour or the weekly window) is used, no new agent step starts. 0 = off. Only applies when the CLI reports a share (a subscription login, not an API key).
  - `#:on-limit` (stop | wait; default stop) — What happens at the threshold: `stop` = the run is handed to a person, with the window and its reset time as the reason; `wait` = the run waits until the window resets and then continues, unless that is further away than #:limit-wait-minutes (then it is handed over).
  - `#:limit-wait-minutes` (integer; default 300) — Longest wait for a reset with #:on-limit wait, in minutes (at least 1).

### `stand-in`

A stand-in for the person a run waits for: a strong model reads what the person would read and decides, inside the scope declared here. Omitted: off, and a person may still switch it on for this machine with `al decider` or the dashboard, where it may then only resume a stopped run. It never overrides a rejected review, never lands work with a protected-path change or a failing required check, never approves its own work, never edits code and never acts on a run a person touched since it stopped; `land` and `promote` only ask the gate again.
Declare at most one. Default when omitted: none.

- **`(stand-in off …)`** — Declared, and off until a person switches it on on this machine.
  - `#:model-set` (tier name: base | heavy | a tier from the agent's #:models; default heavy) — Model tier of the stand-in's calls: a tier declared on the agent of every ADW.
  - `#:may` (list of resume | restart | answer | integrate | settle | land | promote | retry-job; default (resume)) — Decision kinds it may take alone (kind auto). Every other kind it may only suggest.
  - `#:never` (list of resume | restart | answer | integrate | settle | land | promote | retry-job; default ()) — Decision kinds it neither takes nor suggests: those items go to a person as they are.
  - `#:max-actions-per-run` (integer; default 3) — Most actions it takes on one run (and the runs that replace it), 1–20; after that the run goes to a person with the history.
  - `#:max-per-hour` (integer; default 12) — Most actions it takes in this layer per hour, 1–1000.
  - `#:escalate-to` (list of dashboard | notify; default (dashboard)) — Where an item goes when it hands it to a person: `dashboard` = the Needs you list; `notify` = also a message through the notifiers that list needs-human.
  - `#:systemd` (boolean; default #f) — Also generate a systemd user unit (systemd/al-<name>-stand-in.service) that keeps its loop running without the page.

- **`(stand-in suggest …)`** — It proposes; a person answers on the dashboard, with `al answer`, by mail or by webhook.
  - `#:model-set` (tier name: base | heavy | a tier from the agent's #:models; default heavy) — Model tier of the stand-in's calls: a tier declared on the agent of every ADW.
  - `#:may` (list of resume | restart | answer | integrate | settle | land | promote | retry-job; default (resume)) — Decision kinds it may take alone (kind auto). Every other kind it may only suggest.
  - `#:never` (list of resume | restart | answer | integrate | settle | land | promote | retry-job; default ()) — Decision kinds it neither takes nor suggests: those items go to a person as they are.
  - `#:max-actions-per-run` (integer; default 3) — Most actions it takes on one run (and the runs that replace it), 1–20; after that the run goes to a person with the history.
  - `#:max-per-hour` (integer; default 12) — Most actions it takes in this layer per hour, 1–1000.
  - `#:escalate-to` (list of dashboard | notify; default (dashboard)) — Where an item goes when it hands it to a person: `dashboard` = the Needs you list; `notify` = also a message through the notifiers that list needs-human.
  - `#:systemd` (boolean; default #f) — Also generate a systemd user unit (systemd/al-<name>-stand-in.service) that keeps its loop running without the page.

- **`(stand-in auto …)`** — It takes the decisions listed in #:may by itself and proposes the others.
  - `#:model-set` (tier name: base | heavy | a tier from the agent's #:models; default heavy) — Model tier of the stand-in's calls: a tier declared on the agent of every ADW.
  - `#:may` (list of resume | restart | answer | integrate | settle | land | promote | retry-job; default (resume)) — Decision kinds it may take alone (kind auto). Every other kind it may only suggest.
  - `#:never` (list of resume | restart | answer | integrate | settle | land | promote | retry-job; default ()) — Decision kinds it neither takes nor suggests: those items go to a person as they are.
  - `#:max-actions-per-run` (integer; default 3) — Most actions it takes on one run (and the runs that replace it), 1–20; after that the run goes to a person with the history.
  - `#:max-per-hour` (integer; default 12) — Most actions it takes in this layer per hour, 1–1000.
  - `#:escalate-to` (list of dashboard | notify; default (dashboard)) — Where an item goes when it hands it to a person: `dashboard` = the Needs you list; `notify` = also a message through the notifiers that list needs-human.
  - `#:systemd` (boolean; default #f) — Also generate a systemd user unit (systemd/al-<name>-stand-in.service) that keeps its loop running without the page.

### `forge`

The code forge used for issues, PRs and CI integration.
Declare at most one. Default when omitted: `(forge none)`.

- **`(forge none …)`** — No forge: branches stay local, review results are written to the layer.
  - `#:remote` (string; default "") — Optional git remote to push to.

- **`(forge github …)`** — GitHub via the `gh` CLI.
  - `#:repo` (string; default REQUIRED) — owner/name.
  - `#:host` (string; default "github.com") — GitHub host (Enterprise supported).

### `placement`

Where runs of this layer may execute. Omitted: every run executes on the machine that holds the layer, as before. Hosts are `home` (a reserved id: the machine that holds the layer) or the ids of declared (host …) clauses. The address of a host is never written in the layer file: it comes from the variable AL_HOST_<ID> (the id in capitals, `-` as `_`) in the environment, in `local.env` in the layer directory or in `$XDG_CONFIG_HOME/al/<layer name>.env`. A run on another host works in its own clone of the git source and can only push its own branch; the home machine fetches that branch and runs the workflow's (ship) step itself, through the unchanged gate.
Declare at most one. Default when omitted: none.

- **`(placement auto …)`** — A scheduler on the home machine asks every listed host for its load, picks one by #:prefer and starts the run there. `al hosts LAYER status` shows what it sees; `al run LAYER /NAME … --on HOST` picks the host by hand.
  - `#:hosts` (list of symbol; default REQUIRED) — Hosts runs may execute on, in declared order: `home` and/or ids of declared (host …) clauses.
  - `#:prefer` (least-loaded | first; default least-loaded) — `least-loaded`: the host with the lowest share of its runs in use (ties: the lower load average, then a host that already has the sandbox image, then the declared order); `first`: the first listed host with a free run.
  - `#:max-runs-per-host` (integer; default 0) — Runs in flight at once on each host, 1–64; replaces (concurrency #:max-runs) on every host including `home`. 0 = (concurrency #:max-runs) applies on each host.
  - `#:reserve` (((FIELD value) …), see record `host-reserve`; default none) — Keep one host for some work classes, e.g. ((host build-2) (classes (chore bug))): that host only takes runs whose class is fixed at start to one of them.
  - `#:source-env` (string; default "AL_GIT_SOURCE") — NAME of the variable holding the git source: the URL runs clone the base commit from and push their own branch to (the forge's clone URL, or the home repository over ssh). Every machine holds its own value, the URL as seen from there. Never the URL itself.
  - `#:layer-source-env` (string; default "AL_LAYER_SOURCE") — NAME of the variable holding the git source of a layer that is not in the application repository. Never the URL itself.
  - `#:lost-after` (integer; default 120) — Seconds without an answer from a host after which its run is marked `lost`, 30–3600; `al run LAYER --restart RUN` starts it again on another host.

### `dashboard`

A live, read-only work dashboard for this layer (runs in flight, each run's workflow graph, timeline, costs, transcripts, check logs), generated by `al gen` as adws/dashboard.py. Declared by default: observability does not have to be asked for.
Declare at most one. Default when omitted: `(dashboard local)`.

- **`(dashboard local …)`** — A local process: `uv run adws/dashboard.py` serves the page (standard library only, no CDN) and watches this layer plus the #:also layers.
  - `#:port` (integer; default 8765) — TCP port of the page.
  - `#:bind` (string; default "127.0.0.1") — Listen address. Anything other than a loopback address needs #:token-env.
  - `#:also` (list of string; default ()) — Other layer directories (relative to this layer, e.g. "../other.al") watched on the same page.
  - `#:poll-ms` (integer; default 750) — How often the run files are polled, in milliseconds (at least 100).
  - `#:systemd` (boolean; default #f) — Also generate a systemd user unit (systemd/al-<name>-dashboard.service) that keeps it running.
  - `#:token-env` (string; default "") — Environment variable holding an access token every request must carry; required for a non-loopback #:bind.

- **`(dashboard podman …)`** — The same dashboard in its own locked-down rootless podman container: layers mounted read-only, no capabilities, read-only root, an internal network with no route out, only 127.0.0.1:PORT published, a random token per start.
  - `#:port` (integer; default 8765) — Host port published on 127.0.0.1.
  - `#:bind` (string; default "127.0.0.1") — Not used by the container, which publishes on 127.0.0.1 only; kept so that switching between `local` and `podman` is one word.
  - `#:also` (list of string; default ()) — Other layer directories (relative to this layer) watched on the same page; mounted read-only too.
  - `#:poll-ms` (integer; default 750) — How often the run files are polled, in milliseconds (at least 100).
  - `#:systemd` (boolean; default #f) — Also generate a systemd user unit that keeps the container running.
  - `#:token-env` (string; default "") — Not used by the container (it makes a random token per start and prints the URL with it).
  - `#:podman-socket` (boolean; default #f) — Mount the user's podman API socket so the page can show container state, CPU and memory. Off by default for a reason: a podman socket gives the container full control of your podman (start, stop, exec into any container), read-only mount or not.

- **`(dashboard none …)`** — No dashboard is generated.

### `notify`

Tell a person when a run needs them or has ended. Each notifier lists the events it reports: `needs-human` (the run stopped and was handed to a person, including a spending or usage limit stop), `failed` (the run failed and nothing was handed over), `passed` (the run finished; nothing was merged by al), `shipped` (the run finished and its change was merged or deployed). A run reports exactly one of them, at most once per notifier, and a notifier that fails never fails the run. Nothing private is written here: an address, a server or a password is given as the NAME of an environment variable, whose value comes from the environment, from `local.env` in the layer directory (git-ignored, never committed) or from `$XDG_CONFIG_HOME/al/<layer name>.env`. `al notify-test LAYER` sends a test message through every notifier.
Declare any number. Default when omitted: `(notify none)`.

- **`(notify none …)`** — Nothing is sent.

- **`(notify email …)`** — An e-mail over SMTP (standard library only). The message is short: workflow, run id, what happened, where to look.
  - `#:events` (list of needs-human | failed | passed | shipped; default (needs-human failed)) — Events this notifier reports.
  - `#:to-env` (string; default "AL_NOTIFY_TO") — NAME of the environment variable holding the recipient address (several: separated by commas). Never the address itself.
  - `#:from-env` (string; default "AL_NOTIFY_FROM") — NAME of the environment variable holding the sender address. Never the address itself.
  - `#:smtp-url-env` (string; default "AL_NOTIFY_SMTP_URL") — NAME of the environment variable holding the SMTP URL: `smtp://host:port` (plain; only to a loopback host, e.g. a local mail bridge, unless the URL ends in `?insecure=plaintext`), `smtp+starttls://user:pass@host:port` or `smtps://user:pass@host:port`. Never the URL itself.
  - `#:timeout` (integer; default 10) — Seconds one attempt may take, 1–60; after that the run goes on without it.

- **`(notify command …)`** — Run a shell command with the message on standard input (first line: the subject). The generic way out: a chat webhook, a desktop notification, a pager. It runs in the layer directory with the variables of `local.env` in its environment, plus AL_NOTIFY_EVENT and AL_NOTIFY_SUBJECT; exit code 0 means accepted. Its output is discarded.
  - `#:run` (string; default REQUIRED) — Shell command (sh -c). Refer to anything private as $VARIABLE; never write an address, a URL with a token or a password here.
  - `#:events` (list of needs-human | failed | passed | shipped; default (needs-human failed)) — Events this notifier reports.
  - `#:timeout` (integer; default 10) — Seconds one attempt may take, 1–60; after that the command is killed and the run goes on.

### `toolchain`

The tools a layer's environments provide, declared once and pinned with Nix: `(environment nix-devshell #:toolchain ID)`, `(environment podman #:toolchain ID …)` and `(environment home-manager #:toolchain ID)` all take exactly this set from one generated file, env/toolchain-<id>.nix. `al gen` pins nixpkgs in env/flake.lock (committed); `al sandbox LAYER update` re-pins it and `al sandbox LAYER build` builds the sandbox image when the lock or the declaration changed.
Declare any number. Default when omitted: none.

- **`(toolchain nix …)`** — A set of nixpkgs packages plus ready-made feature bundles, from one pinned nixpkgs. For a podman environment the image is built from it with Nix (on the host, or in a builder container pinned by digest when the host has no Nix).
  - `#:packages` (list of string; default ()) — nixpkgs attribute names, e.g. ("python312" "uv" "git").
  - `#:nixpkgs` (string; default "github:NixOS/nixpkgs/nixos-25.05") — nixpkgs flake reference; env/flake.lock pins its exact revision.
  - `#:features` (list of browser | agent-cli | video | build-essentials | docker-cli | podman-cli; default ()) — Ready-made bundles; see `Toolchain features` below for what each adds.
  - `#:env` (list of (NAME VALUE [#:field value …]), see record `env-var`; default ()) — Environment variables, e.g. (("PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD" "1")).
  - `#:shell-hook` (string; default "") — Extra shell hook of the dev shell.

### `environment` — PITER letter E

PITER · Environment: where the agent works. An ADW lists one or more; they stack in order (worktree → nix → podman).
Declare any number. Default when omitted: `(environment worktree)`.

- **`(environment host …)`** — The application checkout itself, no isolation. Only for read-only workflows.
  - `#:read-only` (boolean; default #t) — Refuse steps that are expected to write.

- **`(environment worktree …)`** — A dedicated git worktree per run under the layer (trees/<adw-id>), so the app's working tree is never touched.
  - `#:dir` (string; default "trees") — Worktree parent directory relative to the layer.
  - `#:port-base` (integer; default 9100) — First port of the per-run port block.
  - `#:ports-per-run` (integer; default 2) — Ports reserved per run (exported as ADW_PORT_0..n).
  - `#:copy-files` (list of string; default ()) — Untracked files copied from the app checkout into the worktree (e.g. .env).
  - `#:keep` (never | on-failure | always; default on-failure) — When the worktree is kept after the run.
  - `#:sparse` (list of string; default ()) — Sparse-checkout these directories only (cone mode); empty = full checkout. For large monorepos.
  - `#:gc-days` (integer; default 7) — Kept worktrees of finished runs older than this are removed when a new run starts; 0 = never.
  - `#:delete-merged-branches` (boolean; default #t) — When a run's worktree is removed, delete its branch if it holds nothing that is not already on the default or al/ship branch.
  - `#:prepare` (list of name of a declared cmd; default ()) — Codebase cmds run once per run, in order, after the worktree exists and before the first step, in the run's environment (a container's caches are mounted): dependency installs such as `uv sync`, `bun install`, `cargo fetch`. Shown as a `setup` step; a failure ends the run with that output. With a podman #:devcontainer and no #:prepare, the dev container's postCreateCommand is the prepare step.

- **`(environment nix-devshell …)`** — A Nix flake dev shell generated in the layer; every codebase command and the agent run inside `nix develop`.
  - `#:packages` (list of string; default ()) — nixpkgs attribute names providing the toolchain (e.g. python312 uv); with #:flake, extras added on top of the repository's dev shell. Either this or #:toolchain.
  - `#:toolchain` (name of a declared toolchain, or ""; default "") — A declared (toolchain nix …) that provides the packages; either this or #:packages.
  - `#:nixpkgs` (string; default "github:NixOS/nixpkgs/nixos-unstable") — nixpkgs flake reference (with #:packages only; a toolchain has its own).
  - `#:shell-hook` (string; default "") — Extra shell hook.
  - `#:pure` (boolean; default #f) — Use `nix develop --ignore-environment` (keeps HOME, PATH is nix-only).
  - `#:flake` (string; default "") — Directory of the repository's own flake, relative to its root ("." = top level). Its dev shell #:shell is used (read from the default branch, refreshed at the start of every run); #:packages and #:browser are added on top. Empty = a shell generated from #:packages.
  - `#:shell` (string; default "default") — Name of the dev shell in the repository's flake (devShells.<system>.<name>). Only with #:flake.
  - `#:browser` (boolean; default #f) — Add a headless Chromium (Linux) and set AL_BROWSER and CHROME_BIN to it, for browser tests.

- **`(environment home-manager …)`** — A Home Manager module generated in the layer that installs the toolchain and the layer's helper commands for a user.
  - `#:packages` (list of string; default ()) — nixpkgs attribute names. Either this or #:toolchain.
  - `#:toolchain` (name of a declared toolchain, or ""; default "") — A declared (toolchain nix …) that provides the packages; either this or #:packages.
  - `#:module-name` (string; default "agentic-layer") — Option namespace: programs.<module-name>.enable.
  - `#:state-version` (string; default "25.05") — home.stateVersion used by the standalone example configuration.

- **`(environment podman …)`** — A light rootless podman container; the worktree is bind-mounted, nothing else of the host is visible.
  - `#:base-image` (string; default "docker.io/library/debian:stable-slim") — Base image (with #:packages; not with #:toolchain).
  - `#:packages` (list of string; default ()) — Distribution packages installed in the image (apt names for Debian bases).
  - `#:toolchain` (name of a declared toolchain, or ""; default "") — A declared (toolchain nix …): the image is built from it with Nix instead of from #:base-image and #:packages; #:setup lines are applied as a final layer.
  - `#:setup` (list of string; default ()) — Extra RUN lines for the Containerfile.
  - `#:network` (none | host | slirp; default slirp) — Network mode: `slirp` = podman's default rootless user-mode network, `none` = fully offline checks, `host` = host network.
  - `#:memory` (string; default "4g") — Memory limit.
  - `#:cpus` (string; default "2") — CPU limit.
  - `#:agent-inside` (boolean; default #t) — Run the agent CLI inside the container, so the agent itself is sandboxed (the image must provide the agent CLI). #f = only the codebase commands (the checks) run inside; the agent then runs on the host with the user's own access.
  - `#:scope` (run | command; default run) — `run` = one container per ADW run, every step execs into it (installed dependencies persist for the run); `command` = a fresh container per command.
  - `#:caches` (list of string; default ()) — Named cache volumes shared across runs, mounted at /caches/NAME. Known names also set the tool's cache variable: uv, pip, cargo, go, npm, pre-commit.
  - `#:credentials` (list of claude | codex; default ()) — Agent credentials made available inside the container (read-only auth file + API key variable). Only meaningful with #:agent-inside #t.
  - `#:publish` (list of integer; default ()) — Container ports published on 127.0.0.1 at the run's leased host ports, in order (first → ADW_PORT_0). Every run has its own network namespace, so the app inside always binds its usual ports and runs never collide; publish only what a host-side tool (browser, reviewer) must reach.
  - `#:services` (list of name of a declared service; default ()) — Sidecar services started with the run in the same pod (they share localhost with the run's container) and removed with it.
  - `#:pids-limit` (integer; default 2048) — Process limit inside the container.
  - `#:read-only-root` (boolean; default #f) — Mount the image's root filesystem read-only; the worktree, caches, /tmp and the home directory stay writable.
  - `#:nested-engine` (boolean; default #f) — Give the run's container a rootless podman of its own for tests that build or start containers. It stores everything in a per-run volume, cannot see the host's containers, images or socket, and stays inside the run's network and limits. Adds /dev/fuse to the container and nothing else: every capability stays dropped. One uid inside, so inner images that switch users do not work. The preflight refuses the run where the host cannot provide it.
  - `#:containerfile` (string; default "") — Path of the repository's own Containerfile or Dockerfile, relative to its root. The run builds it (from the run's worktree) as the base image; al adds only a thin final layer (run user home, #:packages, #:setup, #:browser, the agent CLI when #:agent-inside #t, no entrypoint). The repository's file is never edited.
  - `#:target` (string; default "") — Build stage of #:containerfile (podman build --target). Only with #:containerfile.
  - `#:context` (string; default ".") — Build context of #:containerfile, relative to the repository root. Only with #:containerfile.
  - `#:devcontainer` (string; default "") — Path of the repository's dev container file (e.g. .devcontainer/devcontainer.json). Honoured: image or build (dockerfile, context, target), known features, containerEnv, postCreateCommand (as the prepare step), forwardPorts (as published ports). Everything else is listed in env/SOURCE.md and by al gen.
  - `#:browser` (boolean; default #f) — Install a headless Chromium in the image and set AL_BROWSER and CHROME_BIN.

### `service`

Per-run sidecar services (database, cache, mock API). Each run gets its own instances, so parallel runs never share state.
Declare any number. Default when omitted: none.

- **`(service container …)`** — A container started in the run's pod before the first step and removed with the run.
  - `#:image` (string; default REQUIRED) — Image reference, e.g. docker.io/library/postgres:16-alpine.
  - `#:env` (list of string; default ()) — Environment as KEY=VALUE strings.
  - `#:command` (string; default "") — Command override; empty = the image's default.
  - `#:ready-cmd` (string; default "") — Command run inside the sidecar until it exits 0 (e.g. `pg_isready -U postgres`); empty = no wait.
  - `#:ready-timeout` (integer; default 60) — Seconds to wait for readiness.

### `review` — PITER letter R

PITER · Review: how the result is judged and what happens after.
Declare any number. Default when omitted: `(review human)`.

- **`(review human …)`** — Open a pull request and stop. A human reads it (presence = 2: prompt and review).
  - `#:reviewers` (list of string; default ()) — Forge users requested as reviewers.
  - `#:draft` (boolean; default #f) — Open the PR as draft.
  - `#:body-cmd` (name of a declared cmd, or ""; default "") — Codebase command run in the worktree just before the pull request is written; its standard output (markdown) opens the PR description. It gets ADW_STATE (path of the run's state.json) and ADW_BASE (the commit the change is based on).

- **`(review agent …)`** — An agent reviews the diff against the spec, with artefacts as proof, and posts a structured verdict. A human still merges.
  - `#:command` (name of a declared command; default review) — Review command.
  - `#:artefacts` (list of name of a declared artefact; default ()) — Artefacts attached as proof.
  - `#:reviewers` (integer; default 1) — Independent review agents; all must pass ('double agent check').
  - `#:agent` (name of a declared agent, or ""; default "") — Agent the reviewer steps run on; empty = the workflow's agent. A different agent here (another vendor or model) reviews the first one's work. The patch and implement steps of a review round stay on the workflow's agent.
  - `#:max-retries` (integer; default 3) — Patch-and-re-review attempts on blockers before stopping for a human.
  - `#:body-cmd` (name of a declared cmd, or ""; default "") — Codebase command whose standard output opens the PR description (see review human).

- **`(review auto …)`** — Zero-touch: agent review + deterministic gates; if everything passes the change ships without a human.
  - `#:command` (name of a declared command; default review) — Review command.
  - `#:artefacts` (list of name of a declared artefact; default ()) — Artefacts collected, stored and given to the reviewer as proof.
  - `#:reviewers` (integer; default 1) — Independent review agents; all must pass.
  - `#:agent` (name of a declared agent, or ""; default "") — Agent the reviewer steps run on; empty = the workflow's agent (see review agent).
  - `#:max-retries` (integer; default 3) — Patch-and-re-review attempts on blockers.
  - `#:ship` (pr | merge | deploy; default merge) — On pass: open PR only, merge to the default branch, or merge and run the deploy command.
  - `#:deploy-cmd` (name of a declared cmd, or ""; default "") — Codebase command run after merge when ship = deploy.
  - `#:require-checks` (list of name of a declared cmd; default REQUIRED) — Codebase commands that must exit 0 in the final state (the deterministic gate).
  - `#:require` (all | affected; default all) — all = every #:require-checks cmd has a passing result for the exact tree that ships (run at the gate, or reused from the same tree). affected = a required cmd with #:always #f whose #:covers no changed path touches is recorded as not affected instead; the compiler warns when this is combined with #:ship merge or deploy.
  - `#:allowed-classes` (list of chore | bug | feature | patch; default (chore bug)) — Work classes allowed to ship untouched; others fall back to a human PR.
  - `#:max-diff-lines` (integer; default 400) — Larger diffs fall back to a human PR.
  - `#:block-protected-paths` (boolean; default #t) — Any change under codebase protected paths falls back to a human PR.
  - `#:body-cmd` (name of a declared cmd, or ""; default "") — Codebase command whose standard output opens the PR description (see review human).

### `artefact`

Proof a check or review produces. Collected from the worktree after the producing step and put in storage.
Declare any number. Default when omitted: none.

- **`(artefact log …)`** — Captured stdout/stderr of codebase commands (always available).
  - `#:tail-lines` (integer; default 200) — Lines of each log shown to the reviewer.

- **`(artefact junit …)`** — JUnit XML test report.
  - `#:glob` (string; default REQUIRED) — Glob relative to the worktree.

- **`(artefact coverage …)`** — Coverage report (lcov, cobertura xml, or text).
  - `#:glob` (string; default REQUIRED) — Glob relative to the worktree.

- **`(artefact image …)`** — Screenshots or rendered images; the reviewer reads every one.
  - `#:glob` (string; default REQUIRED) — Glob relative to the worktree.
  - `#:max-files` (integer; default 12) — Upper bound handed to the reviewer.

- **`(artefact video …)`** — Screen/session recordings; keyframes are extracted with ffmpeg for the reviewer.
  - `#:glob` (string; default REQUIRED) — Glob relative to the worktree.
  - `#:keyframes` (integer; default 6) — Evenly spaced frames extracted per video.

- **`(artefact audio …)`** — Audio files (e.g. generated speech).
  - `#:glob` (string; default REQUIRED) — Glob relative to the worktree.

- **`(artefact trace …)`** — Tool traces such as Playwright trace.zip.
  - `#:glob` (string; default REQUIRED) — Glob relative to the worktree.

- **`(artefact html …)`** — HTML reports.
  - `#:glob` (string; default REQUIRED) — Glob relative to the worktree.

- **`(artefact file …)`** — Any other file worth keeping.
  - `#:glob` (string; default REQUIRED) — Glob relative to the worktree.

- `build-essentials` — A C compiler and build tools: gcc, gnumake, pkg-config.
- `docker-cli` — The docker client (talks to a daemon you provide).
- `podman-cli` — The podman CLI.

## Records

### `codebase`

The application the layer wraps. Everything codebase-specific that templates need lives here.
  - `#:root` (string; default REQUIRED) — Path of the application checkout, relative to the agentic.rkt file or absolute.
  - `#:languages` (list of symbol; default REQUIRED) — Languages, most important first.
  - `#:default-branch` (string; default "main") — Branch that ships.
  - `#:description` (string; default "") — One-paragraph description used by prime/plan templates.
  - `#:package-manager` (string; default "") — How dependencies are added (e.g. `uv add`, `cargo add`).
  - `#:readme` (string; default "README.md") — Entry document agents read first.

### `cmd`

A named shell command of the codebase: (cmd NAME "shell" …). Check steps and validation sections refer to these names.
  - `#:run` (string; default REQUIRED) — Shell command, run from the worktree root.
  - `#:timeout` (integer; default 1800) — Seconds one run of the command may take; allow for several runs sharing the machine.
  - `#:description` (string; default "") — What the command proves.
  - `#:covers` (list of string; default ()) — Paths this command proves something about, relative to the repository root: a directory ("kit/dashboard"), a file, or a glob ("*.md", "docs/**"). A cmd with #:covers is one of the layer's checks: (check NAME #:cmds affected) runs it, and `al verify` reports source paths no check covers.
  - `#:always` (boolean; default #t) — #t = the command runs for every change. #f = where affected checks are asked for (a check step with #:when-affected #t, a gate with #:require affected) it runs only when a changed path is under its #:covers, and is recorded as not affected otherwise; needs #:covers.
  - `#:reuse` (boolean; default #t) — #t = a passing result is reused when the same command is asked for again on an identical tree in the same run (the gate after a passing check step, a review round that changed nothing). #f = it always runs again: for a command that is not deterministic.
  - `#:targeted` (string; default "") — The targeted form: the command run with the tests selected for a change, e.g. "pytest -q {tests}". Placeholders {tests} (selected test files or ids), {files} (changed files under #:covers), {packages} (Go packages as ./dir, Rust crates as names); at least one. "" = the command has only its full form (#:run).
  - `#:smoke` (string; default "") — The smoke form: a few minutes, always meaningful (e.g. "pytest -q -m smoke"). Run at depth smoke, and at depth targeted when selection finds nothing for a covered change. "" = full instead.
  - `#:select` (list of changed-tests | path-map | imports | coverage | command; default (changed-tests imports)) — Selection strategies, tried in this order and united: changed-tests = test files the change added or modified; path-map = #:path-map; imports = tests that import a changed module (Python, JavaScript/TypeScript, Go packages, Rust crates); coverage = the map recorded by full runs (#:record-coverage); command = #:select-cmd. What earlier batch misses taught is always added.
  - `#:select-cmd` (string; default "") — For `command` in #:select: a shell command printing one test file or id per line; it gets AL_CHANGED (changed files, one per line) and AL_BASE (the commit compared against).
  - `#:path-map` (list of (SOURCE TESTS [#:field value …]), see record `path-map-entry`; default ()) — Declared source → test patterns, e.g. (("kit/runtime/adw_modules/{name}.py" "kit/runtime/tests/test_{name}*.py")).
  - `#:test-root` (string; default "") — Directory, relative to the repository root, that {tests}, {files} and {packages} are relative to: the directory the command changes into ("kit/runtime" for "cd kit/runtime && pytest -q {tests}"). Selected paths outside it are dropped.
  - `#:max-targeted` (integer; default 200) — More tests selected than this: run the full form instead, and say so.
  - `#:record-coverage` (none | coverage-py | profile-dir | al-json; default none) — How a full run records which test executed which file: coverage-py = coverage.py JSON with contexts (coverage json --show-contexts); profile-dir = a directory with one lcov (.info) or Go cover profile per test, named after the test; al-json = al's own format. Needs #:coverage-run and #:coverage-file.
  - `#:coverage-run` (string; default "") — The full form with the runner's per-test coverage on, run instead of #:run when a full run records coverage.
  - `#:coverage-file` (string; default "") — File or directory, relative to the repository root, #:coverage-run writes the recipe's output to.
  - `#:needs-home` (boolean; default #f) — The command needs state that exists only on the machine that holds the layer (a local database, a licence, a device): a workflow that runs it as a check or script is never placed on another host.

### `path-map-entry`

One ("SOURCE" "TESTS") pair of a cmd's #:path-map.
  - `#:source` (string; default REQUIRED) — Source pattern relative to the repository root; {name} matches one file name without extension, {dir} one or more directories.
  - `#:tests` (string; default REQUIRED) — Test glob relative to the repository root; {name} and {dir} are filled from the source.

### `paths`

Where things are: (paths #:source (…) #:tests (…) …).
  - `#:source` (list of string; default ()) — Source directories.
  - `#:tests` (list of string; default ()) — Test directories.
  - `#:docs` (list of string; default ()) — Documentation directories.
  - `#:protected` (list of string; default ()) — Paths agents must not change without a human (CI config, release, security, migrations…).

### `conditional-doc`

(conditional-doc "path" "condition" …): documentation an agent must read when the condition holds.
  - `#:path` (string; default REQUIRED) — Document path relative to the codebase root.
  - `#:when` (string; default REQUIRED) — Condition in plain language.

### `command`

(command NAME #:template T …): instantiate a kit template as a command of this layer.
  - `#:template` (prime | install | start | plan-feature | plan-bug | plan-chore | plan-patch | plan-layer-change | implement | build | test | resolve-test | e2e-test | review | document | commit | pull-request | classify | branch-name | summarize | question | self-improve | track-kpis | custom; default REQUIRED) — Kit template to instantiate.
  - `#:description` (string; default "") — One-line purpose.
  - `#:file` (string; default "") — For template custom: path of a hand-written template relative to the layer.
  - `#:model-set` (tier name: base | heavy | a tier from the agent's #:models; default base) — Model tier the command runs on: a tier declared on the agent that runs it (base, heavy, or one from #:models).
  - `#:output` (text | json | path; default text) — What the command must return: free text, JSON per its schema, or a file path.
  - `#:focus` (list of string; default ()) — Codebase-specific instructions injected into the template's Instructions section.
  - `#:relevant` (list of string; default ()) — Codebase paths listed under Relevant Files; empty = codebase source+tests paths.
  - `#:validation` (list of name of a declared cmd; default ()) — Codebase commands listed as Validation Commands.
  - `#:fabric` (list of symbol; default ()) — Fabric patterns vendored into the layer and applied by this command.
  - `#:may-commit` (boolean; default #f) — Whether a run step of this command may commit (move HEAD in the worktree). The commit template always may; every other step's HEAD, refs and the layer directory are checked after it and a change fails the step.

### `hop`

(hop NAME #:template T …): a higher-order prompt — it takes another prompt, plan or command as its argument.
  - `#:template` (run-plan | meta-command | meta-adw | meta-expert | plan-build-improve; default REQUIRED) — Kit HOP template.
  - `#:description` (string; default "") — One-line purpose.
  - `#:takes` (prompt | plan | command | spec; default prompt) — What the argument is.
  - `#:produces` (changes | command | adw | expert | plan; default changes) — What comes out.
  - `#:model-set` (tier name: base | heavy | a tier from the agent's #:models; default heavy) — Model tier the HOP runs on (see command).

### `expert`

(expert NAME …): an agent expert — an expertise file the agent maintains itself (act → learn → reuse).
  - `#:domain` (string; default REQUIRED) — What the expert knows, in one sentence.
  - `#:paths` (list of string; default REQUIRED) — Codebase paths the expertise is validated against.
  - `#:max-lines` (integer; default 1000) — Line cap of the expertise file.

### `adw`

(adw NAME … (steps STEP …)): an AI Developer Workflow. The four PITER choices default to the first declared option of each family.
  - `#:description` (string; default "") — One-line purpose.
  - `#:input` (list of name of a declared prompt-input; default the first declared option of that family) — Prompt inputs this ADW accepts.
  - `#:trigger` (list of name of a declared trigger; default the first declared option of that family) — Triggers that may start it.
  - `#:environment` (list of name of a declared environment; default the first declared option of that family) — Environment stack, outermost first.
  - `#:review` (name of a declared review; default the first declared option of that family) — Review option.
  - `#:agent` (name of a declared agent; default the first declared option of that family) — Agent the steps run on.
  - `#:classes` (list of chore | bug | feature | patch; default ()) — Work classes routed to this ADW by classification; empty = any.
  - `#:changes` (codebase | layer; default codebase) — What the ADW changes. `codebase`: the application. `layer`: an agentic layer (its codebase is the repository that holds a layer, as in the workflow `al improve` runs); such an ADW never ships without a person and is exempt from the in-repo layer protection.
  - `#:deliver-to` (name of a declared stage, or ""; default "") — Stage this workflow delivers into; "" = the first stage that accepts the run's class. Only with declared stages.

### `stage`

(stage NAME #:branch "…" …): a named place where work accumulates.
  - `#:branch` (string; default REQUIRED) — Branch name or pattern; placeholders {cycle} and {version} (only on the cycle's stage) and {date} (the cycle's opening date on the cycle's stage, else the run's UTC start date).
  - `#:from` (name of a declared stage, or ""; default "") — Stage this one is cut from; "" = none (the final stage).
  - `#:into` (name of a declared stage, or ""; default "") — Stage it is delivered into when accepted; "" = #:from.
  - `#:accepts` (list of chore | bug | feature | patch; default (chore bug feature patch)) — Work classes routed here by default (the first declared stage that accepts a class gets it).
  - `#:agents-may-merge` (boolean; default #t) — Whether a zero-touch workflow may merge into it; #f = only people change it (runs end in a pull request).
  - `#:entry` (merge | squash | rebase | fast-forward; default merge) — How a change enters it.
  - `#:checks` (list of name of a declared cmd; default ()) — Codebase cmds that must hold on it: added to the review's #:require-checks for runs delivering here.
  - `#:deploy-cmd` (name of a declared cmd, or ""; default "") — Codebase cmd that deploys this stage; used by a review with #:ship deploy that has no #:deploy-cmd of its own.
  - `#:environment-name` (string; default "") — Where the deploy lands, in words (e.g. staging, production); shown in the run summary and by al explain.
  - `#:frozen` (list of string; default ()) — Periods closed to new deliveries, each "YYYY-MM-DD..YYYY-MM-DD" (UTC, both days included): a run that would deliver then ends `waiting` at its deliver step and says until when.
  - `#:frozen-while-promoting` (boolean; default #f) — Closed to new deliveries while a promotion out of this stage is open.

### `version-change`

How a promotion changes the repository's version: (bump major|minor|patch) or (keep).
  - `#:how` (bump | keep; default REQUIRED) — bump: raise the version where the repository keeps it (VERSION, pyproject.toml, package.json, Cargo.toml; else the latest vX.Y.Z tag); keep: use the version it has.
  - `#:level` (major | minor | patch; default patch) — Which part a bump raises.

### `promotion`

(promotion FROM -> TO …): how a stage's work moves into the next stage — evidence for the people who accept it, a recorded decision, then merge, version, tag, deploy and back-merge. Run with `al promote LAYER FROM TO`; every non-final stage without one gets one with these defaults.
  - `#:from` (name of a declared stage; default REQUIRED) — The stage whose branch is promoted.
  - `#:to` (name of a declared stage; default REQUIRED) — The stage it goes into: FROM's #:into (default #:from).
  - `#:approval` (human | agent | auto; default human) — human: people approve (al decide, the dashboard, or an approving review / `/approve` on the pull request); agent: independent reviewer agents review the whole stage diff and the pack; auto: no approval. agent and auto only into a stage with #:agents-may-merge #t.
  - `#:approvers` (integer; default 1) — human: distinct people who must approve; agent: reviewer agents that must all pass. 1–9.
  - `#:requires` (list of checks | acceptance; default (checks acceptance)) — checks: the #:checks of FROM and TO pass on the stage head; acceptance: every change is accepted or refused (or the whole promotion approved) before it merges.
  - `#:method` (merge | squash | fast-forward | cherry-pick; default merge) — How the stage enters TO.
  - `#:version` ((HOW LEVEL [#:field value …]), see record `version-change`; default none) — The version change, e.g. (bump minor); none = the version is not touched.
  - `#:tag` (string; default "") — Tag on the promoted commit; placeholders {version} {cycle} {date}; "" = no tag.
  - `#:present` (list of summary | changes | proof | demo | checks | notes | excluded; default (summary changes proof demo checks notes excluded)) — Sections of the presentation pack: summary, per-change details with acceptance criteria, proof (pictures, recordings), demo (one page to open and show), checks on the stage head, release notes and changelog entry, what is not included.
  - `#:after` (list of symbol; default ()) — (deploy) or (deploy ENV): after merging, run TO's #:deploy-cmd; ENV must equal TO's #:environment-name.
  - `#:back-merge` (list of name of a declared stage; default ()) — Stages the promoted result is merged back into (an agent round resolves a conflict). A hotfix promotion (FROM is cut from TO) defaults to every other stage that accepts a class.
  - `#:adw` (name of a declared adw, or ""; default "") — Workflow whose environment, agent, review command and #:patch/#:implement commands the promotion's agent rounds use; "" = the first workflow that delivers into FROM, else the first workflow.

### `model-tier`

One model tier of an agent, written (TIER "MODEL-ID" [#:effort LEVEL]) inside #:models.
  - `#:tier` (tier name: base | heavy | a tier from the agent's #:models; default REQUIRED) — Tier name: lowercase letters, digits and dashes (not `inherit`).
  - `#:model` (string; default REQUIRED) — Model id passed to the agent CLI.
  - `#:effort` (default | low | medium | high | xhigh | max; default default) — Reasoning effort for this tier: `default` leaves it to the CLI. Claude Code: passed as --effort (low…max). codex: passed as -c model_reasoning_effort=LEVEL (low…xhigh; codex has no flag of its own for it). Not available for custom agents.

### `env-var`

One environment variable of a toolchain, written ("NAME" "VALUE") inside #:env.
  - `#:name` (string; default REQUIRED) — Variable name: letters, digits and _, not starting with a digit.
  - `#:value` (string; default REQUIRED) — Value.

### `step-run`

(run NAME #:command C …): one agent, one prompt, one purpose.
  - `#:command` (name of a declared command-or-hop; default REQUIRED) — Command or HOP to execute.
  - `#:args` (list of string; default ()) — Arguments; $prompt, $plan, $adw_id, $class, $branch and $out.<step> are substituted.
  - `#:model-set` (tier name: base | heavy | a tier from the agent's #:models; default inherit) — Model tier for this step; `inherit` = the command's, unless the request names a tier (a task-file tag or issue keyword).
  - `#:retries` (integer; default 0) — Re-run on failure.
  - `#:when` (always | class-feature | class-bug | class-chore | class-patch; default always) — Run only for this work class.
  - `#:agent` (name of a declared agent, or ""; default "") — Agent for this step only; empty = the ADW's agent. Use it for a cheaper model on routine steps or a different vendor for an independent step.

### `step-check`

(check NAME #:cmd C …): a deterministic feedback loop. Runs a codebase command; on failure an agent resolves and the command re-runs. (check NAME #:cmds affected …) stands for one check step per codebase cmd that declares #:covers, each named after its cmd, with #:when-affected #t and the other fields as written.
  - `#:cmd` (name of a declared cmd; default REQUIRED) — Codebase command.
  - `#:resolve` (name of a declared command, or ""; default "") — Command given the failing output; empty = fail the run immediately.
  - `#:retries` (integer; default 3) — Resolve attempts.
  - `#:collect` (list of name of a declared artefact; default ()) — Artefacts collected after the command.
  - `#:in` (name of a declared environment, or ""; default "") — Environment option the command runs in, together with the ADW's worktree: a podman option (its own container, e.g. one with #:nested-engine #t) or a nix-devshell option (on the host). "" = the ADW's own environment stack. The gate's re-run of the same cmd runs there too.
  - `#:max-skipped` (integer; default -1) — The check fails when more tests than this were skipped (counted from the output of pytest, go test, cargo test, mocha or a collected JUnit report); -1 = no limit. With a limit set, output al cannot count fails the check.
  - `#:forbid-skip-reason` (string; default "") — The check fails when a skipped test's reason contains this text (case-insensitive), e.g. "no podman"; "" = none. Skips without a visible reason then fail it too (pytest: -rs, go test: -v).
  - `#:when-affected` (boolean; default #f) — #t = the step runs its cmd only when the run's changed paths (against the run's base; in a review round, since the cmd last passed) touch the cmd's #:covers, or the cmd is #:always #t. Not run, it is recorded as not affected with the paths compared, never as passed. A layer change, a changed path no check of the workflow covers, and a changed file two #:always #f checks cover run it anyway.

### `step-script`

(script NAME #:cmd C …): run a declared codebase cmd as a workflow step, e.g. a workflow script the team already has. It runs in the run's environment (worktree, container), gets the run context in environment variables (ADW_ID, ADW_PROMPT, ADW_CLASS, ADW_PLAN, ADW_BRANCH, ADW_WORKTREE, ADW_LAYER_DIR, ADW_RESUME), its output becomes the step's output ($out.NAME), and a non-zero exit fails the run, unless the exit code is one of its #:waiting-exit codes: then the run ends as `waiting`, and `--resume` runs the step again with ADW_RESUME=1 (empty otherwise). It is not a check: no resolve loop, and the gate does not count it as verification.
  - `#:cmd` (name of a declared cmd; default REQUIRED) — Codebase command to run.
  - `#:args` (list of string; default ()) — Arguments appended to the command, each shell-quoted; $prompt, $plan, $adw_id, $class, $branch and $out.<step> are substituted.
  - `#:timeout` (integer; default 0) — Seconds; 0 = the cmd's own #:timeout.
  - `#:waiting-exit` (list of integer; default ()) — Exit codes that mean the script is waiting for something outside (e.g. 75): the run ends as `waiting` (not failed, not passed), keeps its worktree and prints how to resume; `--resume` runs this step again with ADW_RESUME=1.
  - `#:journal` (string; default "") — A folder the script writes its own run journal to, relative to the run's worktree; {adw_id} is the run id. While the script runs, each line of its events.jsonl is mirrored into the run's events (script.event) and each inner step's prompt.md and output files become documents of the run. A missing folder is not an error.

### `step-review`

(review [NAME] …): run the ADW's review option here.
  - `#:patch` (name of a declared command, or ""; default "") — Command that plans a patch for a blocker; implemented via the ADW's implement command.
  - `#:implement` (name of a declared command-or-hop, or ""; default "") — Command/HOP that implements the patch plan.

### `step-ship`

(ship [NAME]): apply the review option's ship policy (PR / merge / deploy). Must come after a review step.
  - `#:message` (string; default "") — Extra text for the PR/merge message.

### `step-fan-out`

(fan-out NAME #:adw CHILD …): run COUNT independent candidate runs of the child ADW (same prompt and class, each in its own worktree, branch, container and slots), pick a winner and merge its commits into this run's worktree, so later steps work on them. The child must commit its work and must not ship. Every candidate holds one `runs` slot and so does the parent: #:max-runs of (concurrency slots …) must exceed the number of concurrent parents plus candidates.
  - `#:adw` (name of a declared adw; default REQUIRED) — The child ADW each candidate runs.
  - `#:count` (integer; default 3) — Number of candidates, 2–8.
  - `#:pick` (best | first | all; default best) — `best`: of the passing candidates, the one with the fewest resolve attempts, then the smallest diff, then the earliest; `first`: the first to pass; `all`: every candidate must pass and all are merged in order.
  - `#:max-parallel` (integer; default 0) — Candidates running at once; 0 = #:count.

### `host`

(host #:id ID …): what a machine that runs this layer must have, written with keywords only and declared once per kind of machine. From it `al gen` writes three committed provisioning files under the layer, env/hosts/<id>/home-manager.nix, env/hosts/<id>/nixos.nix and env/hosts/<id>/provision.sh, which hold no host name, user, address or secret: those are only known on the host. `al deploy --as ID --provision` shows the plan, asks once and applies it; `al deploy --status` lists the drift.
  - `#:id` (symbol; default "host") — Name of this kind of machine: lowercase letters, digits and dashes, no dots (it is not a host name). `al deploy --as ID` picks it.
  - `#:provision` (none | home-manager | nixos | script; default none) — How the machine is provisioned: `none` = al installs nothing and only checks; `home-manager` = a Home Manager module; `nixos` = a NixOS module (privileged rebuild); `script` = a POSIX shell script for Debian/Ubuntu, Fedora and Arch.
  - `#:units` (list of cron | webhook | dashboard; default ()) — Units kept running on this machine; empty = every unit the layer declares.
  - `#:dashboard-port` (integer; default 0) — Port of the dashboard on this machine; 0 = the layer's own (dashboard #:port).
  - `#:linger` (boolean; default #t) — Enable lingering, so the units keep running after the user logs out.
  - `#:images` (build | pull | load; default build) — Where the sandbox image comes from: `build` = the host builds it at the first run; `pull` = from the (registry …), as pushed by `al sandbox push`; `load` = streamed over the ssh connection by `al deploy`.
  - `#:fallback-build` (boolean; default #t) — When the image on the host was built from another env/Containerfile (its recipe hash differs): #t = untag it so the host builds at the first run; #f = stop the deploy.

### `registry`

(registry #:address-env VAR …): the container registry `al sandbox push|pull` and hosts with #:images pull use. It holds only the NAMES of environment variables, whose values come from the environment, `local.env` in the layer or `$XDG_CONFIG_HOME/al/<layer name>.env`. Declared at most once.
  - `#:address-env` (string; default "AL_REGISTRY") — NAME of the variable holding the registry address and repository prefix, e.g. registry.example.org/team. Never the address itself.
  - `#:username-env` (string; default "") — NAME of the variable holding the registry user; empty = no login.
  - `#:password-env` (string; default "") — NAME of the variable holding the registry password or token; given together with #:username-env.
  - `#:tls-verify` (boolean; default #t) — Verify the registry's TLS certificate.

### `testing`

(testing DEPTH #:k v …): how deep a run's checks go and how the whole is proven per batch. Declared at most once; without it every check runs its full form (the layer predates targeted testing). Depths: targeted (the tests a change concerns), full (whole suites), smoke (each cmd's #:smoke). #:escalate ((paths "G" …) (diff-lines N) (files N) (lockfile) (layer) (unmapped) (class C …)) and #:batch ((every N) (after-hours H)) are written as lists and stand for the escalate-… and batch-… fields.
  - `#:depth` (targeted | full | smoke; default targeted) — The layer's depth: the default of #:per-run and #:review-rounds.
  - `#:per-run` (inherit | targeted | full | smoke; default inherit) — Depth of a run's check steps and its gate; inherit = DEPTH.
  - `#:review-rounds` (inherit | targeted | full | smoke; default inherit) — Depth of the re-checks of a review round, selected from what the patch touched; inherit = DEPTH.
  - `#:on-stage` (targeted | full | smoke; default full) — Depth of a batch: on a stage head (cycle closed, before a promotion is offered, the batch rhythm) and on the default branch.
  - `#:batch-every` (integer; default 0) — Run a batch after this many changes landed on a branch since its last batch; 0 = not by count.
  - `#:batch-after-hours` (integer; default 0) — Run a batch when a change landed and the last batch is older than this many hours; 0 = not by time.
  - `#:escalate-paths` (list of string; default ()) — Core areas: a changed path matching one of these globs runs this run at full depth.
  - `#:escalate-diff-lines` (integer; default 1500) — A change of more lines than this runs at full depth; 0 = no limit.
  - `#:escalate-files` (integer; default 40) — A change of more files than this runs at full depth; 0 = no limit.
  - `#:escalate-on` (list of lockfile | layer | unmapped; default (lockfile layer unmapped)) — lockfile = a dependency manifest or lock file changed; layer = the agentic layer changed; unmapped = a changed path under a cmd's #:covers that no selection strategy could map to a test.
  - `#:escalate-classes` (list of chore | bug | feature | patch; default ()) — Work classes that always run at full depth.
  - `#:on-batch-failure` (list of bisect | open-fix | revert; default (bisect open-fix)) — bisect = find the delivered run that broke the batch (failing tests only, on the commits since the last green batch); open-fix = start a fix run with the failing tests, the culprit and its plan; revert = prepare a revert branch, and ask the fix run to revert where agents may merge.
  - `#:fix-adw` (name of a declared adw, or ""; default "") — Workflow a fix run uses; "" = the first workflow that accepts class bug.
  - `#:max-miss-percent` (integer; default 10) — A command whose miss rate over its last 50 batch-verified targeted runs exceeds this falls back to full and says so; 0 = never.

### `host-reserve`

A reservation of (placement … #:reserve …), written as pairs: ((host ID) (classes (CLASS …))).
  - `#:host` (symbol; default REQUIRED) — The reserved host: one of #:hosts, not `home`.
  - `#:classes` (list of chore | bug | feature | patch; default REQUIRED) — Work classes the host is kept for; at least one.

## Delivery presets

`(delivery PRESET #:param value …)` stands for the (stage …) and (cycle …) clauses below. A (stage NAME …)
with the name of one of its stages replaces that stage in place; a stage with another name is added.
Without any stage or preset, runs use (codebase #:default-branch …) as their base and target.

### `(delivery trunk …)`

Trunk-based: every change goes straight into the main branch (through a pull request where a forge exists).
  - `#:main` (string; default "main") — The main branch; equals (codebase #:default-branch …).
  - `#:entry` (merge | squash | rebase | fast-forward; default squash) — How a change enters the main branch.

Expands to (defaults):

```racket
(stage main #:branch "main" #:entry squash)
```

### `(delivery sprint …)`

Sprints: work collects in a branch per sprint (sprint/{cycle}); a person accepts the sprint into main. Agents never merge into main.
  - `#:main` (string; default "main") — The main branch; equals (codebase #:default-branch …).
  - `#:length-days` (integer; default 14) — Days per sprint.
  - `#:name` (string; default "{year}-s{week}") — Name of a sprint (see (cycle sprint …) #:name).
  - `#:accepts` (list of chore | bug | feature | patch; default (feature bug chore patch)) — Work classes that go into the sprint.

Expands to (defaults):

```racket
(cycle sprint #:stage sprint #:length-days 14 #:name "{year}-s{week}")
(stage sprint #:branch "sprint/{cycle}" #:from main #:accepts (feature bug chore patch) #:entry merge)
(stage main #:branch "main" #:accepts () #:agents-may-merge #f)
```

### `(delivery gitflow …)`

Gitflow: work collects in develop; a release branch per version is cut from develop and merged into main by a person; hotfix branches are cut from main and take the bugs a workflow delivers there (#:deliver-to hotfix). Agents only merge into develop.
  - `#:main` (string; default "main") — The main branch; equals (codebase #:default-branch …).
  - `#:develop` (string; default "develop") — The integration branch work is delivered into.

Expands to (defaults):

```racket
(cycle release #:stage release #:name "{version}")
(stage develop #:branch "develop" #:from main #:accepts (feature bug chore patch) #:entry merge)
(stage release #:branch "release/{version}" #:from develop #:into main #:accepts () #:agents-may-merge #f)
(stage hotfix #:branch "hotfix/{date}" #:from main #:into main #:accepts (bug) #:agents-may-merge #f)
(stage main #:branch "main" #:accepts () #:agents-may-merge #f)
```

### `(delivery release-train …)`

A release train: work collects in a train branch that leaves on a schedule (every #:length-days days) or per version (#:length-days 0); a person merges the train into main.
  - `#:main` (string; default "main") — The main branch; equals (codebase #:default-branch …).
  - `#:length-days` (integer; default 14) — Days per train; 0 = a versioned train (one per `al cycle start --version V`), whose #:name must contain {version}.
  - `#:name` (string; default "{date}") — Name of a train (see (cycle …) #:name).

Expands to (defaults):

```racket
(cycle sprint #:stage train #:length-days 14 #:name "{date}")
(stage train #:branch "train/{cycle}" #:from main #:accepts (feature bug chore patch) #:entry merge)
(stage main #:branch "main" #:accepts () #:agents-may-merge #f)
```

### `(delivery phase-gate …)`

Phase gates: work enters the first phase branch (phase/NAME); a person promotes it through each later phase and finally into main.
  - `#:main` (string; default "main") — The main branch; equals (codebase #:default-branch …).
  - `#:phases` (list of symbol; default (build verify accept)) — Phase names in order; agents deliver into the first.

Expands to (defaults):

```racket
(stage build #:branch "phase/build" #:from main #:into verify #:accepts (feature bug chore patch))
(stage verify #:branch "phase/verify" #:from main #:into accept #:accepts () #:agents-may-merge #f)
(stage accept #:branch "phase/accept" #:from main #:into main #:accepts () #:agents-may-merge #f)
(stage main #:branch "main" #:accepts () #:agents-may-merge #f)
```

## Examples (both compile)

### minimal.rkt

```racket
#lang al
;; The smallest useful layer: every PITER choice is the default
;; (cli prompt, manual trigger, git worktree, human PR review, Claude Code, local artefacts).
(agentic-layer #:name "minimal"
  (codebase #:root "../app" #:languages (python)
    (cmd test "uv run pytest -q"))
  (command plan #:template plan-chore #:model-set heavy #:output path #:validation (test))
  (hop implement #:template run-plan #:takes plan)
  (adw plan-build
    (steps
      (run plan #:command plan #:args ("$prompt"))
      (run build #:command implement #:args ("$out.plan"))
      (check test #:cmd test))))
```

### full.rkt

```racket
#lang al
;; A layer that uses most of the vocabulary: several prompt inputs and triggers,
;; a stacked environment, artefacts on S3, and a zero-touch (auto review → merge) ADW
;; next to a human-reviewed one, model tiers, a second vendor as reviewer, spending limits, and a
;; script step that runs one of the team's own scripts, notifications when a run needs a person, and
;; delivery into a sprint branch (with a hotfix route a person merges), and a placement that says where runs execute.
;; The sandbox is built from a pinned Nix toolchain; the dev shell keeps the older #:packages form.
(agentic-layer #:name "webshop" #:description "Agentic layer for the webshop monorepo"
  (codebase #:root "../webshop" #:languages (typescript python) #:default-branch "main"
            #:description "Vue storefront + FastAPI backend" #:package-manager "bun add / uv add"
    (cmd install "bun install && (cd api && uv sync)" #:timeout 1200)
    (cmd lint "bun run lint && (cd api && uv run ruff check)")
    (cmd test "bun run test -- --reporter=junit --outputFile=reports/unit.xml && (cd api && uv run pytest -q)"
         #:covers ("web" "api")
         ;; a change runs the tests it concerns; the whole suite runs per batch (see (testing …) below)
         #:targeted "uv run --project api pytest -q {tests}"
         #:select (changed-tests path-map imports)
         #:path-map (("api/app/{dir}/{name}.py" "api/tests/{dir}/test_{name}.py"))
         #:smoke "(cd api && uv run pytest -q -m smoke)")
    (cmd e2e "bun run e2e" #:timeout 1800 #:description "Playwright; writes e2e-results/"
         #:covers ("web") #:always #f)   ; only run where affected checks are asked for and web/ changed
    (cmd deploy "./scripts/deploy.sh staging" #:needs-home #t)   ; the deploy key is on the machine that holds the layer
    (cmd changelog "./scripts/changelog.sh" #:description "the team's own script: appends the change to CHANGELOG.md")
    (paths #:source ("web/src" "api/app") #:tests ("web/tests" "api/tests") #:docs ("docs")
           #:protected (".github" "api/migrations" "scripts/deploy.sh"))
    (conditional-doc "docs/payments.md" "When touching anything under api/app/payments"))

  (layer sibling)
  (forge forgejo #:host "https://forgejo.example.org" #:repo "acme/webshop")
  (storage s3 #:bucket "webshop-adw" #:endpoint "https://s3.example.org")
  (voice kokoro)
  (agent claude-code #:models ((fast "claude-haiku-5-5") (heavy "claude-fable-5-2" #:effort high)))
  (agent codex #:id second-opinion)
  (budget limits #:run-usd 5 #:step-usd 2 #:day-usd 50 #:limit-stop-percent 90 #:on-limit wait #:limit-wait-minutes 120)
  (stand-in suggest #:may (resume restart) #:max-per-hour 6)
  (notify email #:events (needs-human failed shipped))   ; addresses and the server: variables in local.env, never here
  (registry #:address-env "AL_REGISTRY" #:username-env "AL_REGISTRY_USER" #:password-env "AL_REGISTRY_PASSWORD")
  (notify command #:id desktop #:run "notify-send \"$AL_NOTIFY_SUBJECT\"" #:events (needs-human))

  (prompt-input issue #:labels ("adw"))
  (prompt-input tasklist)
  (prompt-input voice #:route auto)
  (trigger webhook #:port 8001)
  (trigger cron #:interval-seconds 15 #:systemd #t)
  (trigger voice)
  (trigger manual)

  (toolchain nix #:id dev #:packages ("bun" "nodejs_22" "python312" "uv" "git" "curl") #:features (browser agent-cli video))
  (environment worktree #:copy-files (".env"))
  (environment nix-devshell #:packages ("bun" "nodejs_22" "python312" "uv" "ffmpeg"))
  (environment podman #:id sandbox #:toolchain dev #:network slirp #:caches ("npm" "uv"))

  (artefact log)
  (artefact junit #:glob "reports/*.xml")
  (artefact image #:id screenshots #:glob "e2e-results/**/*.png")
  (artefact video #:id recordings #:glob "e2e-results/**/*.webm" #:keyframes 6)

  (review human)
  (concurrency slots #:max-runs 4 #:max-agents 2)
  ;; where runs may execute: only here. Another machine is a declared (host #:id build-1 …) of an in-repo layer,
  ;; listed as #:hosts (home build-1), and may be kept for some classes: #:reserve ((host build-1) (classes (chore bug)))
  (placement auto #:hosts (home) #:prefer least-loaded #:max-runs-per-host 4)
  (dashboard local #:port 8765 #:also ("../storefront.al") #:systemd #t)
  (review auto #:id zero-touch #:artefacts (log junit screenshots recordings) #:agent second-opinion
          #:ship deploy #:deploy-cmd deploy #:require-checks (lint test e2e)
          #:allowed-classes (chore bug) #:max-diff-lines 300)
  (delivery sprint #:length-days 14)   ; every change collects in sprint/{cycle}; a person accepts the sprint into main
  ;; urgent bugs go to their own branch, cut from main; only a person merges it back into main
  (stage hotfix #:branch "hotfix/{date}" #:from main #:into main #:accepts (bug) #:agents-may-merge #f #:environment-name "production")
  (promotion sprint -> main #:approval human #:approvers 1 #:version (bump minor) #:tag "v{version}")   ; a person accepts the sprint; main gets a version, a tag and a changelog entry
  (promotion hotfix -> main #:approval human #:approvers 2)   ; an urgent fix needs two people and is merged back into the sprint
  ;; checks run the tests a change concerns; the full suites run once per 5 landed changes, and a
  ;; change to the API schema, a lock file, the layer or a path no test maps to runs everything
  (testing targeted #:batch ((every 5)) #:escalate ((paths "api/schema/**") (lockfile) (layer) (unmapped)))

  (command prime #:template prime)
  (command classify #:template classify #:model-set fast #:output json)
  (command chore #:template plan-chore #:model-set heavy #:output path #:validation (lint test))
  (command bug #:template plan-bug #:model-set heavy #:output path #:validation (lint test e2e))
  (command feature #:template plan-feature #:model-set heavy #:output path #:validation (lint test e2e)
           #:fabric (create_prd)
           #:focus ("New endpoints need a pytest module under api/tests mirroring the source path."))
  (command resolve-test #:template resolve-test #:model-set heavy)
  (command review #:template review #:model-set heavy #:output json #:fabric (review_code))
  (command patch #:template plan-patch #:model-set heavy #:output path)
  (command document #:template document)
  (command commit #:template commit #:model-set fast #:fabric (create_git_diff_commit))
  (command pull-request #:template pull-request #:fabric (write_pull-request))
  (hop implement #:template run-plan #:takes plan)
  (hop new-command #:template meta-command #:produces command)
  (hop new-adw #:template meta-adw #:produces adw)

  (expert payments #:domain "Payment provider integration and reconciliation" #:paths ("api/app/payments"))

  (adw plan-build #:description "Plan and implement, nothing else" #:input (issue tasklist voice)
    (steps
      (run classify #:command classify #:args ("$prompt"))
      (run plan-chore #:command chore #:args ("$prompt") #:when class-chore)
      (run plan-bug #:command bug #:args ("$prompt") #:when class-bug)
      (run plan-feature #:command feature #:args ("$prompt") #:when class-feature)
      (run build #:command implement #:args ("$plan"))))

  (adw sdlc #:description "Plan, build, test, review; a human merges"
       #:input (issue tasklist) #:trigger (webhook cron manual)
       #:environment (worktree nix-devshell) #:review human
    (steps
      (compose plan-build)
      (check lint #:cmd lint #:resolve resolve-test)
      (check test #:cmd test #:resolve resolve-test #:collect (junit))
      (run document #:command document #:args ("$plan"))
      (script changelog #:cmd changelog #:args ("$prompt") #:waiting-exit (75) #:journal ".work/changelog/{adw_id}")
      (run commit #:command commit)
      (review)
      (ship)))

  (adw zte #:description "Zero-touch: ships chores and bugs when every gate passes"
       #:input (issue tasklist) #:trigger (webhook cron)
       #:environment (worktree nix-devshell sandbox) #:review zero-touch #:classes (chore bug)
    (steps
      (compose plan-build)
      (check lint #:cmd lint #:resolve resolve-test)
      (check test #:cmd test #:resolve resolve-test #:collect (junit))
      (check e2e #:cmd e2e #:resolve resolve-test #:retries 2 #:collect (screenshots recordings) #:when-affected #t)
      (run commit #:command commit)
      (review #:patch patch #:implement implement)
      (ship)))

  (adw hotfix #:description "Urgent bugs: straight to a hotfix branch, a person merges"
       #:input (issue tasklist) #:trigger (webhook manual)
       #:environment (worktree nix-devshell) #:review human #:classes (bug) #:deliver-to hotfix
    (steps
      (compose plan-build)
      (check test #:cmd test #:resolve resolve-test)
      (run commit #:command commit)
      (review)
      (ship)))

  (adw candidate #:description "One candidate of a race: plan, build, test, commit; never ships"
       #:input (tasklist) #:trigger (manual) #:environment (worktree nix-devshell) #:review human
    (steps
      (compose plan-build)
      (check test #:cmd test #:resolve resolve-test)
      (run commit #:command commit)))

  (adw race #:description "Three candidates race (two at a time); a human reviews the best one"
       #:input (tasklist) #:trigger (manual) #:environment (worktree nix-devshell) #:review human
    (steps
      (fan-out race #:adw candidate #:count 3 #:pick best #:max-parallel 2)
      (check lint #:cmd lint #:resolve resolve-test)
      (check test #:cmd test #:resolve resolve-test #:collect (junit))
      (review)
      (ship))))
```
